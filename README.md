# 영화 네비게이터

한국 영화와 **그 인물이 참여한 외국 영화**를 하나의 그래프로 잇고,
인물이라는 다리를 건너 **근거와 함께** 답하는 GraphRAG 에이전트.

**▶ [movie-navigator.vercel.app](https://movie-navigator.vercel.app)**
— 답변 문장을 보려면 우측 상단 **설정**에서 OpenAI 키를 넣는다.
키 없이도 근거(작품·인물·다리)와 3D 는 그대로 나온다.

## 왜 만들었나

영화 질문에는 **한 문서만 읽어서는 답이 안 나오는 것**이 있다.

```
"송강호와 이선균이 함께 출연한 영화는?"

  《기생충》 줄거리:
    "전원 백수로 살 길 막막하지만 사이는 좋은 기택 가족…"
    → '송강호' 도 '이선균' 도 한 글자도 없다
```

**키워드·벡터 검색이 여기서 무너진다.** 배우 이름은 어느 줄거리에도 들어 있지 않다.
두 사람의 출연 목록을 각각 펼쳐 **겹치는 곳**을 봐야만 답이 나온다.

```
"기생충에서 기우를 연기한 배우가 출연한 좀비 영화는?"

  기생충 ──[기우]──▶ 최우식 ──출연──▶ 부산행
```

《부산행》 문서에 '기생충'은 없고, 《기생충》 문서에 '부산행'은 없다.
**최우식이라는 다리를 건너야만** 닿는다. 색인 시점에 그 다리를 놓아 두는 것이 이 프로젝트다.

## 측정을 믿을 수 있게 만든 것

**답이 맞는지 1초면 안다** — 이 프로젝트가 영화를 고른 이유다.
정답을 판단할 수 없는 도메인에서는 "재현율 90%" 같은 숫자를 만든 사람조차 검증할 수 없다.

그래서 평가셋 152문항 중 **143문항을 사용자가 직접 썼다.** 정답도 직접 매겼다.

실제로 그 덕에 잡힌 오류가 여럿이다 — 작성자가 기억으로 붙인 정답 100개 중 3개가
TMDB 전체 크레딧과 어긋났고(염정아는 《타짜》에 출연하지 않는다),
반대로 시스템이 맞았는데 정답이 틀려서 실패로 집계된 문항도 있었다.

> **기억은 이 프로젝트에서 여섯 번 틀렸다.** 작성자도, 나도.
> '없음' 판정은 전수를 봐야 성립한다 — 부분만 보고 "없다"고 하면
> 시스템이 맞을 때 틀렸다고 채점하게 된다.

최근 둘은 **시스템이 찾아냈다.** "최민식과 황정민이 함께 출연한 영화는?" 의 정답이
《남산의 부장들》로 적혀 있었는데 그 영화 **전체 크레딧 30명에 둘 다 없고**,
"박해일이 세종대왕을 연기한 영화는?" 의 정답 《나랏말싸미》에서 **세종대왕은 송강호**다
(박해일은 신미 스님). 두 번 다 시스템이 맞았다
(→ [고도화](#시스템이-평가셋의-오류를-찾아냈다)).

## 측정 결과

**컨텍스트 재현율** — 정답에 필요한 작품을 근거로 데려왔는가.
LLM 없이 계산되므로 비용이 0이고, 여기서 못 데려온 것은 뒤에 어떤 모델을 붙여도 답에 못 쓴다.

### 홀드아웃 — 코드를 동결한 뒤 한 번만 채점한 숫자

| | 그래프 | BM25 |
|---|---|---|
| **동결 시점** | **79%** | 62% |
| 그 결과를 보고 고친 뒤 | 94% | 62% |
| 말뭉치를 1,721 → 3,072편으로 넓힌 뒤 | 95% | 61% |
| 정답이 틀린 문항 둘을 바로잡은 뒤 | **97%** | 61% |

**79%가 일반화를 말할 수 있는 유일한 숫자다.** 뒤의 둘은 그 문항들을 보고 고친 것이다.
셋 다 남겨 둔다 — 격차 15%p 가 과적합의 크기다.

말뭉치를 두 배로 넓혔을 때 **한 번 89%까지 떨어졌다가** 95%로 올라왔다.
떨어진 다섯 문항을 열어 보니 말뭉치 크기가 원인인 것은 하나도 없었고,
전부 **원래 있던 결함이 후보가 늘면서 드러난 것**이었다 (→ [고도화](#고도화--부딪히고-고친-것들)).

### 유형별 — 그래프가 이기는 자리는 분명하다

| 유형 | 그래프 | BM25 | |
|---|---|---|---|
| **인물 교집합** (A와 B가 함께 나온 영화) | **19/19** | **0/19** | ★ |
| **다리 건너기** (배역 → 배우 → 다른 작품) | **11/11** | 1/11 | ★ |
| **수상** | 3/3 | 1/3 | ★ |
| 작품 교집합 (A·B·C에 모두 나온 배우) | 15/15 | 13/15 | |
| 배역명으로 배우 찾기 | 22/22 | 21/22 | |
| 개봉 연도 | 9/9 | 9/9 | |
| 인물 → 작품 | 14/14 | 7/14 | |
| **줄거리 내용으로 찾기** | **7/9** | **7/9** | ← 그래프가 도울 게 없다 |
| **전체** | **105/107** | **63/107** | |

**BM25 0/19 는 성능 차이가 아니라 원리적 불가능이다.** 줄거리에 배우 이름이 없으므로
어떤 텍스트 검색으로도 두 사람의 공통작을 구할 수 없다.

반대로 줄거리 질문("반지하 가족이 부유한 집에 차례로 취업하며…")은 답이 한 문서 안에
있으므로 그래프가 할 일이 없다. **이기는 자리와 지는 자리를 나눠서 재는 것**이 이 평가의 핵심이다.

### 근거가 맞을 때 답도 맞는가 — 따로 재야 했다

위의 숫자는 전부 **컨텍스트 재현율**이다. "정답에 필요한 근거를 데려왔는가" 만 잰다.
그런데 근거가 완벽한데 답변 문장만 고장난 적이 있고, **그때 숫자는 한 칸도 안 움직였다.**

그래서 답변을 따로 채점한다 (`pnpm eval:answer`). 기준을 **모델이 실제로 본 근거 블록**에
대고 세운다 — 근거에 없는 것을 못 말한 것은 이 층의 잘못이 아니기 때문이다.

|  | 답변이 말함 | 답변이 못 말함 |
|---|---|---|
| **근거에 답 있음** | 128 | **1** ← 이 층의 손실 |
| 근거에 답 없음 | 0 | 2 ← 재현율 쪽 손실 |

**근거가 답을 담고 있을 때의 답변 정확도 — 128/129 (99%).**
층을 만들자마자 22건이 나왔고(82%), 원인을 하나씩 고쳐 7건까지, 그 7건의 원인이던
**수집 결손**까지 고쳐 1건까지 줄였다 (→ [고도화](#근거는-완벽한데-답이-틀렸다)).
재현율 105/108 은 그 사이 **한 번도 움직이지 않았다.**

남은 1건은 **고칠 자리가 없다.** "이창동 감독이 《시》로 2010년 칸 영화제에서 받은 상은?"
— 위키데이터에 이창동의 수상 서술은 3건뿐이고 칸 각본상이 없다. 영화 《시》 항목에는
수상 서술이 **아예 0건**이다 (직업 필터를 완전히 빼고 질의해서 확인했다).

그런데 이 문항이 '근거에 답 있음' 칸에 앉아 있는 것은 **채점기의 오탐**이다. 근거 블록
안의 `각본상` 글자는 같이 딸려 온 고레에다 히로카즈의 《괴물》이 받은 칸 각본상이다.
채점기는 블록 전체에서 글자를 찾으므로 그것을 이창동 것으로 친다. 모델은 **거절한 것이 맞았다.**

고치면 이 층의 손실이 0 이 되지만 고치지 않았다. **내 숫자를 좋게 만드는 방향의
채점 규칙 변경**이기 때문이다. 앞서 채점 규칙을 한 번 고친 적이 있는데(→ 아래),
그때는 반대 방향이었다. 같은 손으로 양쪽을 하면 숫자를 믿을 수 없게 된다.

"근거에 답 없음 × 답변 맞음" 칸이 0 인 것도 같이 본다 — **근거에 없는 것을 말한 적이 없다.**

### 답하지 않는 것도 기능이다

| | |
|---|---|
| 범위 밖 거절 (예매·스트리밍 위치) | **4/4** |
| 전제가 사실이 아닌 질문 | **4/5** |
| 참/거짓 판별 (틀린 전제를 섞어 놓은 문항) | **10/11** |

세 가지는 성격이 다르다.

```
⛔ 거절       "파묘 어디서 볼 수 있어?"
              → 이 도구가 다룰 범위가 아니다

🚫 전제 오류   "추격자·황해·곡성에 모두 출연한 배우는?"
              → 찾아봤더니 **그런 배우가 없다.** 겹치는 건 감독 나홍진뿐이다
```

거절은 "모른다"이고, 전제 오류는 **"찾아본 결과 사실이 아니다"** 라 더 강한 주장이다.
공통점은 하나 — **답을 지어내지 않는다.**

## 수집 범위 — 연대가 아니라 "선이 생기는가"

"초기 영화부터 다 넣으면?"을 실측했다.

| 구간 | 전체 | 투표 20+ |
|---|---|---|
| 1980년 이전 | 1,931편 | **9편** |
| 전체 | 14,546편 | 1,049편 |

이 측정이 **20표 문턱의 근거였는데, 옛 영화에만 맞는 근거였다.** 아래 고도화 참조.

옛 영화는 TMDB에 **제목만 있고 줄거리도 출연진도 없다.**
이 프로젝트는 관계로 답하므로 출연진이 없으면 **노드는 들어와도 선이 안 생긴다.**
연대로 자르는 대신 이 기준으로 잘랐다 — 《하녀》(1960)도 조건만 맞으면 들어온다.

```
① 한국 영화 2,212편     투표 5+ · 줄거리 있음 · 출연진 3명 이상
② 외국 영화   860편     ①의 인물을 따라 1홉 확장
③ 평가셋 지정 수집       인기와 무관하게 — 정답이 말뭉치에 없어서 틀리는 일을 막는다
```

처음엔 투표 20표로 잘랐다가 **5표 + 출연진 3명**으로 바꿨다. 인기가 아니라
**관계를 만들 사람이 있는가**가 진짜 기준이기 때문이다 (→ [고도화](#수집-기준을-인기에서-데이터로)).

②가 **국경을 넘는 다리**를 만든다. ①만 넣으면 "부산행 나온 배우가 마블에도 나왔다"가
성립하지 않는다.

**규모:** 영화 3,072 · 인물 27,282 · 엣지 63,530 · 수상 169편 473건 + 인물 1,234명 6,040건 · 한글 별칭 1,534명

## 구조

```
scripts/fetch-movies.ts   TMDB → data/raw.json
scripts/fetch-awards.ts   위키데이터 → data/awards.json   (TMDB 에 수상 정보가 없다)
scripts/build-graph.ts    → data/graph.json + 품질 보고서
scripts/evaluate.ts       그래프 vs BM25 (LLM 0회)
scripts/ask.ts            질문 하나를 터미널에서

lib/graph.ts     탐색 — 경로별 예산, 순수 함수
lib/route.ts     5갈래 라우팅 · 씨앗 찾기 · 도메인 게이트 · 전제 검사
lib/romanize.ts  한글 ↔ 로마자 배역명 대조
lib/followup.ts  이어지는 질문 — "그중에 상 받은 건?"
lib/answer.ts    답변 문장 생성 (유일하게 LLM 을 부르는 곳)
lib/ask.ts       질의 파이프라인 (LLM 호출 없음)
lib/bm25.ts      한국어 바이그램 BM25

app/             질문 · 작품 탐색기 · 지도 + 오른쪽 붙박이 3D · 설정(키 입력)
```

**관계 추출에 LLM을 쓰지 않는다.** 출연·연출은 TMDB 크레딧에 명시돼 있어 지어낼 여지가 없다.

### 배역명이 로마자로만 온다

TMDB는 `language=ko-KR`로 요청해도 배역명을 현지화하지 않는다
(배역명 4,022개 중 한글은 19개). 한글을 로마자로 바꿔 대조하되, **표기가 표준을 따르지 않는다:**

```
자성 → Ja-sung   (국어의 로마자 표기법이면 Ja-seong)
안   → Ahn       (표기법이면 An)
```

정확한 변환이 목적이 아니라 **같은 이름인지 판정**이 목적이므로, 양쪽을 같은 규칙으로
뭉갠 뒤 음절 경계에서 대조한다. **17/17 일치.**

## 답변 문장 — LLM 은 마지막에만

`lib/answer.ts` 가 **유일하게 LLM 을 호출하는 곳**이다 (OpenAI `gpt-4.1-mini`).
탐색·라우팅·조립에는 LLM 이 한 줄도 없다. 무엇을 근거로 데려왔는지를 모델 없이
검증할 수 있어야 하고, 그래서 평가가 **비용 0** 으로 돌아간다.

**2겹으로 막는다.**

```
코드 층     근거가 없거나 전제가 틀렸으면 호출 자체를 하지 않는다
            → 호출하지 않으면 지어낼 기회가 없다
프롬프트 층  "아래 근거에만 있는 사실을 쓰라. 없으면 없다고 하라.
            네가 따로 아는 영화 지식을 끌어오지 마라"
```

모델에 넘기는 근거는 **화면에 뜨는 것과 같은 내용**이다. 둘이 어긋나면 사용자가 검증할 수 없다.
답변은 근거 위에 두되 근거를 지우지 않는다 — 무엇을 보고 말했는지 확인할 수 있어야 한다.

## 이어지는 질문

```
"송강호가 나온 영화 알려줘"     → 기생충, 살인의 추억, 설국열차 …
"그중에 상 받은 건 어떤거야?"   → 《기생충》 (새로 찾지 않았다)
```

`그중 · 거기서 · 방금 · 위에서` 같은 말이 나오면 **직전 근거를 그대로 물려받아 거른다.**
수상 여부 · 국적 · 연도 · 평점 · 장르로 거를 수 있다.

LLM 에게 대화 이력을 주고 다시 찾게 할 수도 있었지만, 그러면 **검색 경로에 LLM 이 들어가**
이 프로젝트의 성질이 깨진다. 거를 조건을 못 찾으면 **이어붙이기를 포기하고 그 이유를 말한다** —
억지로 이으면 엉뚱한 답이 나오는데 사용자는 왜 그런지 알 수 없다.

## 화면

```
┌────────────────────────┬────────────────────────┐
│  질문 / 작품 탐색기 / 지도  │   3D (붙박이)           │
└────────────────────────┴────────────────────────┘
```

세 화면은 **서로 독립**이다. 서로를 링크하지 않고, 각자 **주제만** 3D에 넘긴다.
왼쪽에서 무엇을 보든 오른쪽이 따라 바뀐다.

3D의 Y축은 **홉 거리**다 — 질문에서 출발해 인물을 몇 번 건넜는가.
선 위에 뜨는 이름이 **다리의 정체**이고, 한국/외국은 색으로 갈린다.

## 고도화 — 부딪히고 고친 것들

처음부터 이렇게 생기지 않았다. **틀린 답이 하나 나올 때마다 원인을 한 층씩 거슬러 올라간
기록**이다. 증상 → 원인 → 조치 순으로 적는다.

### 수집 — 없는 것은 찾을 수 없다

검색을 아무리 고쳐도 **말뭉치에 없으면 답이 안 나온다.** 실패의 절반은 수집 쪽이었다.

| 증상 | 원인 | 조치 |
|---|---|---|
| "곡성에 나온 배우" 에 김윤석이 없었다 | 출연진을 **상위 10명**만 받았다 | 30명으로. 답이 주연에만 있지 않다 |
| "전도연과 설경구가 함께 나온 영화" → 없다 | 《생일》(2019)이 말뭉치에 없었다 | 평가셋 작품은 **인기와 무관하게 지정 수집** |
| 한국 배우의 외국 작품이 안 잡혔다 | 한국 영화만 수집했다 | 2편 이상 나온 인물 3,474명을 따라 1홉 확장 → 외국 703편 |
| 수상 질문에 답할 게 없었다 | **TMDB 에 수상 정보가 없다** | 위키데이터 SPARQL 로 별도 수집, TMDB ID 로 결합 |
| "상 받은 배우" 와 "상 받은 영화" 가 섞였다 | 작품 수상만 모았다 | 인물 수상을 따로 (996명 4,961건) |

평가셋 지정 수집은 순서가 중요하다. 인기순으로만 자르면 **평가가 검색 품질이 아니라
수집의 구멍을 재게 된다** — 못 맞힌 이유가 "탐색이 못 갔다" 인지 "애초에 없다" 인지
구별이 안 된다.

### 이름이 하나가 아니다 — 별칭

가장 오래 못 찾은 버그다.

```
"아이유가 나온 영화 알려줘"
  → "아이유가 나온 영화는 근거에 확인되지 않습니다"

  …그런데 화면 아래에는 아이유 출연작들이 떠 있었다.
```

**TMDB 의 인물명은 '이지은' 이다.** '아이유'는 `also_known_as` 에만 들어 있었다.
말뭉치에 2편 이상 있는 인물 3,474명의 별칭을 조회해 **514명분**을 채웠다.
마동석 = 돈 리, 이병헌 = Byung-hun Lee 도 같은 문제다.

그런데 별칭을 채우고도 처음엔 안 고쳐졌다. **인물을 대조하는 코드가 세 군데에
복사돼 있었기 때문이다** (`seedsFromPerson` · `seedsFromPersonAward` · `ask.ts`).
한 곳만 고치면 나머지 두 경로로 들어온 질문은 그대로 틀린다.

> 지금은 `peopleIn()` 한 곳에서만 사람을 찾는다.
> **아이유만 고쳐진 게 아니라 514명 전부, 그리고 모든 질문 경로에 적용된다.**
> "한 군데를 고쳤는데 증상이 그대로" 는 대개 같은 일이 여러 군데에서 벌어지고 있다는 뜻이다.

### 탐색 — 멀리 가는 것보다 안 나가는 게 어렵다

```
"송강호가 나온 영화 알려줘"
  답은 3편인데 화면에는 12편이 떴다
```

탐색이 씨앗에서 한 홉 더 나가 **송강호와 같이 나온 사람들의 다른 작품**까지 끌고 왔다.
"X 가 나온 영화" 의 답은 **정확히 X 의 작품**이다. 밖으로 나가면 답이 아니라 소음이다.

그래서 질문 갈래마다 **나갈 수 있는 예산을 따로 뒀다** (`ROUTE_PLAN`).
`filmography` · `cast` 는 예산이 **0** 이다 — 다리를 건너야 하는 질문과
건너면 안 되는 질문은 반대 방향으로 튜닝된다.

그 밖에 이 단계에서 추가된 것:

- **교집합 씨앗** — 두 사람을 각각 펼친 뒤 겹치는 곳에서 시작한다. BM25 가 0/19 인 자리
- **씨앗 사이 다리** — 결과들이 한 사람을 공유하면 그 선을 그린다. 화면에서 왜 같이 나왔는지 보인다
- **배역 → 배우 → 작품** 3단 경로
- **[이어지는 질문](#이어지는-질문)** — 직전 근거를 물려받아 거른다

### 로마자가 너무 잘 맞는다 — 용언이 이름으로 읽힌다

```
"호랑이가 나오고 포수와 대결하는 영화가 어떤거지?"
  → 씨앗에 《바람이 분다》·《경성학교》·《죠죠의 기묘한 모험》이 들어왔다
```

**`나오고` 가 배역명으로 읽혔다.**

```
나오고 → na·o·go
Naoko  → na·o·ko → na·o·go      (표기 보정용 k→g 규칙에 걸렸다)
```

`나오` 는 퍼지 없이도 `Nao`·`Naho` 와 글자 그대로 같다. 로마자 변환은 틀리지 않았다 —
**`나오다` 가 한국어에서 흔한 용언이라는 것**이 문제다.

앞서 만든 "네 편 이상에 걸치면 흔한 말" 규칙은 이걸 못 잡는다. `나오고` 는 2편뿐이다.
**걸러야 할 것이 빈도가 아니라 품사였다.** 둘을 넣었다.

1. **용언 어미로 끝나는 어절에서는 배역 후보를 뽑지 않는다.**
   이름으로 끝날 수 있는 꼬리(서·지·나·은)는 **일부러 뺐다** — 넣으면 은서·민지·유나·지은이
   전부 날아간다. 이름에 안 쓰이는 어미만 담는다.
2. **작품이 지목되지 않았다면, 질문이 배역을 묻고 있을 때만 전역으로 훑는다.**
   말뭉치에 배역명이 4,022개 있다. 두세 글자 덩어리를 전부와 대조하면 우연히 겹치는 것이
   거의 언제나 나오고, 그것이 **진짜 씨앗을 앞자리에서 밀어낸다.**

2번의 표지는 평가셋에 대고 맞췄다 — `character` 22문항 중 **21문항**이 걸린다
(나머지 하나는 제목 두 개가 지목된 감독 질문이라 작품 범위로 좁히는 분기로 간다).
`지역`·`역사`·`통역` 의 '역' 은 앞 글자를 보고 제외한다.

> 고친 뒤 평가셋 숫자는 **한 칸도 움직이지 않았다** (전체 103/107 · 홀드아웃 62/66).
> 답을 더 맞히는 변경이 아니라 **답이 아닌 것을 덜 데려오는 변경**이라 그렇다.
> 재현율만 보면 안 보이고, 화면을 봐야 보인다.

### 묻는 방식이 검색을 흐린다

```
"세종대왕에 대한 이야기가있는 영화 알려줘"
  → "세종대왕에 대한 이야기가 있는 영화는 근거에 없습니다"

  …말뭉치에는 《천문: 하늘에 묻는다》(2019)와 《신기전》(2008)이 있다.
```

BM25 순위를 열어 보니 천문이 **6위**였다. 씨앗은 상위 3개만 쓰므로 떨어졌다.

```
 1. 알파고    2. 무서운 이야기 2    3. 배트맨: 이어 원
 4. 라푼젤: 끝나지 않은 이야기      5. 오징어 게임… 이야기      6. 천문 ←
```

**'이야기' 가 제목에 '이야기' 가 든 작품들을 끌어올렸다.** IDF 가 흔한 말을 깎아 주지만,
**묻는 방식에서 온 말**까지는 깎지 못한다. 그래서 질문 쪽에서만 상투어를 걷어낸다
(알려줘·추천·영화·이야기·관련된·대한·나오는…). 색인에서는 빼지 않는다 —
《무서운 이야기》는 진짜 제목이다. 걷어내니 천문이 **1위**가 됐다.

함께, **확실한 단서(제목·인물·수상)가 하나도 없을 때만** 키워드 씨앗을 3 → 6개로 늘렸다.
그런 질문일수록 순위가 흔들리는데 상위 3개만 보는 것은 순위를 너무 믿는 것이다.

#### 못 고친 것 — 바이그램은 낱말 가운데를 자른다

```
세종대왕 → 세종 · 종대 · 대왕
  세종 → 천문 · 신기전          정확
  종대 → 강남 1970              김종대, 줄거리에 3회 — 그래서 1위였다
  대왕 → 신과함께(염라대왕) · 역린 · 툼 레이더
```

세 조각 중 **둘이 엉뚱하다.** 한국어 조사 문제(봉준호가 / 봉준호의)를 풀려고 글자
바이그램을 쓰는데, 그 대가로 복합어 가운데가 잘린다. 형태소 분석기를 붙이는 것이
정공법이고, 지금은 **알면서 감수하는 비용**으로 남겨 둔다.

### 수집 기준을 인기에서 데이터로

```
"제주도에 관련된 영화 중 민간인을 빨갱이로 죽인 사건을 다룬 영화가 뭐야?"
  → 《최후의 증인》(1980) 입니다           ← 지리산·6.25 영화다. 제주도가 아니다.
```

찾아야 할 답은 **《지슬: 끝나지 않은 세월 2》**(2013, 오멸) 였는데 말뭉치에 없었다.
TMDB 에 물어보니 **13표**여서 투표 20표 문턱에 잘려 있었다. 그런데 데이터는 멀쩡했다 —
줄거리 211자, 출연 21명, 감독, 포스터까지.

문턱의 근거는 "표가 적으면 정보가 부실하다" 였고, 그 측정은 **1980년 이전 영화로 한 것**이었다.
현대 독립영화에는 맞지 않는다. 한국 영화는 TMDB 투표 수가 전반적으로 낮아서,
《영웅》(2022)·《야구소녀》(2020)·《군산: 거위를 노래하다》(2018)가 **전부 19표**다.
인기로 자르면 작품이 아니라 **관객 수를 자르게 된다.**

그래서 기준을 바꿨다. 투표 수는 **비용을 줄이는 1차 거름망**으로 내리고(5표),
진짜 기준은 크레딧을 받아 본 뒤 **출연진이 3명 이상인가**로 뒀다.
관계로 답하는 도구이므로 그것이 실제로 필요한 조건이다.

| | 전 | 후 |
|---|---|---|
| 한국 영화 | 1,018편 | **2,212편** |
| 외국 영화 | 703편 | **860편** |
| 한글 별칭 | 514명 | **1,534명** |

**②-b 단계에서 걸러진 것은 2,303편 중 56편(2.4%)뿐이었다.** 즉 20표 문턱이 자르고 있던 것은
"데이터 없는 작품" 이 아니라 **그냥 덜 알려진 작품**이었다. 대리 지표를 직접 측정으로
바꾸자 드러났다.

### 말뭉치를 두 배로 키웠더니 점수가 떨어졌다

홀드아웃이 **94% → 89%** 로 내려갔다. "데이터를 줄일까" 가 먼저 떠올랐지만,
떨어진 다섯 문항을 전부 열어 보니 **말뭉치 크기가 원인인 것은 하나도 없었다.**

#### ① 흔한 말과 같은 이름 (3문항)

```
"현빈과 손예진이 함께 **주연을** 맡은 영화는?"
  peopleIn → 손예진 · 현빈 · **주연**        ← 이 이름의 인물이 실제로 있다
  교집합 세 사람 → 공통작 0 → "함께 나온 작품이 없습니다"
```

배역명에 쓰던 흔한말 목록을 인물 이름에도 적용했다. 같은 뿌리의 사고가 하나 더 있었다 —
별칭 '이선' 을 가진 작가가 "**이선**균이" 에 걸렸는데, 중복 제거를 **본명끼리** 하고 있어서
살아남았다(`"이선균".includes("이맹유")` 는 거짓이다). **실제로 걸린 글자**로 비교하게 고쳤다.

#### ② 확실한 단서가 BM25 를 막고 있었다 (1문항)

```
"독일 기자를 태운 택시기사가 **1980년** 광주로 향하는 영화는?"

BM25 순위      1위 《택시운전사》 42.79점
실제 씨앗      《1980》 · 《19》          ← BM25 는 호출조차 되지 않았다
```

'1980년' 이 《1980》(2024)이라는 **제목**에 걸렸고, 제목은 "확실한 단서" 라서
`findSeeds` 가 거기서 돌아가 버렸다. **검색은 이미 정답을 1위로 갖고 있었다.**

이 함정은 전에 한 번 겪고 배역 씨앗에 대해서만 고쳐 뒀던 것이다(《부산행》 사고).
**같은 함정의 다른 입구였다.** 이제 **어떤 씨앗도 BM25 를 막지 않는다** —
순서가 이미 우선순위를 표현하고, 넘치는 것은 근거 예산이 자른다.

#### ③ 질문이 준 두 번째 조건을 버리고 있었다 (2문항)

```
"《버닝》에서 종수를 연기한 배우가 **조태오로** 출연한 영화는?"    → 《베테랑》
"…광해군을 연기한 배우가 출연한 **김지운 감독** 영화는?"        → 《좋은 놈, 나쁜 놈, 이상한 놈》
```

배우는 맞게 찾아 놓고 그 사람의 작품을 **전부** 담았다. 유아인 16편에서 《베테랑》이
근거 예산(10편) 밖으로 밀렸다. **말뭉치가 커질수록 한 사람의 작품이 늘어 이 손실이 커진다** —
근거를 더 담는 것으로는 못 막고, 질문이 이미 준 조건을 쓰는 것이 맞다.
배역명과 감독으로 좁히게 하자 **다리 건너기가 11/11 로 처음 만점**이 됐다
(1,721편 시절에도 못 풀던 문항까지 풀렸다).

#### ④ 동명이작을 인기순으로 골랐다

```
"송강호는 《살인의 추억》, 《괴물》, 《기생충》에 모두 출연했다"  → 시스템: 아니다
```

《괴물》이 두 편이 됐다 — 봉준호(2006)와 고레에다(2023). 제목 대조가 **인기순으로**
2023년작을 골라서, 맞는 말이 거짓으로 채점됐다. 수상 결합에서 이미 겪고 TMDB ID 로
풀었던 문제가 이번엔 제목 매칭에서 나왔다.

고친 방식은 **고르지 않는 것**이다. 같은 제목을 묶어서 넘기고, 공통 인물이 나오는 조합을
쓰게 했다. **어느 《괴물》인지는 인기가 아니라 질문의 나머지가 정한다.**

#### 그래서

| | 1,721편 | 3,072편 (처음) | 3,072편 (고친 뒤) |
|---|---|---|---|
| 전체 | 103/107 | 98/107 | **104/107** |
| 홀드아웃 | 62/66 | 59/66 | **63/66** |
| 다리 건너기 | 10/11 | 8/11 | **11/11** |

> **큰 말뭉치는 더 어려운 시험이었고, 그 시험이 원래 있던 결함 네 개를 드러냈다.**
> 1,721편일 때의 96% 는 파이프가 더 좋아서가 아니라 함정을 덜 밟았기 때문이다.
> 데이터를 줄였다면 숫자는 돌아왔겠지만 **결함은 그대로 남았을 것이다.**

### 답이 아닌데 답이라고 한다 — 조건이 여럿일 때

```
질문   제주도 + 민간인 + 빨갱이
답변   "《최후의 증인》입니다"      ← '빨갱이' 만 맞다. 제주도는 줄거리에 없다.
```

"조건을 전부 확인하라" 고 프롬프트에 적어도 고쳐지지 않았다. 모델에게 **대조를 시키는 대신
대조 결과를 건네주는** 쪽으로 바꿨다 — 글자가 있는지 없는지는 코드가 틀릴 수 없다.

```
[조건 대조 — 코드가 근거 본문에서 직접 세어 본 것]
질문의 낱말: 제주도 · 민간인 · 빨갱이 · 죽인
**4개를 모두 담은 작품은 근거에 없다.** 가장 많이 맞은 것도 2개다.
- 《최후의 증인》 : 맞음 빨갱이·죽인 / 없음 제주도·민간인
```

처음엔 낱말마다 따로 찾게 했는데 그것은 틀린 설계였다 — '제주도' 가 《올레》에 있고
'빨갱이' 가 《최후의 증인》에 있다고 해서 **둘 다 가진 작품이 있는 것은 아니다.**
질문이 묻는 것은 결합이므로 **작품 단위로** 센다.

#### 그리고 이 수정이 멀쩡하던 것을 깨뜨렸다

같은 배우를 세 가지로 물었더니 **근거 12편은 똑같은데 답만 갈렸다.**

```
"황정민 배우가 나온 영화"      → 호프·곡성·서울의 봄·신세계…   맞다
"황정민이 출연한 영화"         → "확인되지 않습니다"           틀렸다
"황정민이 주연으로 나온 영화"   → "확인되지 않습니다"           틀렸다
```

대조 블록이 근거의 **제목·줄거리**에서 낱말을 찾는데, **사람은 줄거리에 안 적혀 있다 —
출연진에 적혀 있다.** 그래서 "황정민이 나온 작품은 없다" 는 거짓을 모델에게 건넸고,
모델은 규칙대로 그것을 믿고 거절했다.

```
"황정민 배우가 나온 영화"    → 낱말 [황정민]         1개 → 블록 생략 → 정상
"황정민이 출연한 영화"       → 낱말 [황정민, 출연한]  2개 → 블록 생성 → 거짓 전달
```

'배우'·'나온' 은 잡음 목록에 있었고 '출연한'·'주연' 은 없었다. **조사 하나 차이로 답이 갈렸다.**

단어를 더 넣는 것은 두더지 잡기라, 도는 **조건 자체**를 바꿨다 —
**그래프가 관계로 답을 만들어 냈으면 글자 대조는 할 일이 없다.**
이 블록이 필요한 것은 인물·배역·교집합을 아무것도 못 잡고 줄거리만 남은 질문이다.

> 이 고장은 **평가셋이 잡지 못했다.** 평가는 컨텍스트 재현율만 재는데
> 근거 12편은 세 번 다 완벽했기 때문이다. **답변 문장은 채점 대상이 아니다** —
> 숫자로는 안 보이고 화면을 봐야 보이는 종류다.

### "지목했는데 없다" 와 "아무도 지목하지 않았다"

```
"제주도를 배경으로 만든 영화 알려줘"
  → 질문의 전제가 사실과 다릅니다
     범위 밖이라는 뜻이 아니라, 찾아본 결과입니다

  …《계춘할망》·《지슬》·《올레》·《낙원의 밤》이 다 말뭉치에 있다.
```

'**만든 영화**' 라는 표현 때문에 *인물의 작품* 질문으로 분류됐고, 인물이 하나도 안
잡히자 전제 오류로 막았다. 그런데 이 문장에서 만든 주체는 **아무도 지목되지 않았다** —
제주도는 장소다. 전제가 틀린 게 아니라 **질문을 잘못 읽은 것**이다.

전제 오류는 거절보다 강한 주장이라 더 조심해야 한다. 그래서 둘을 가른다 —
**누군가를 지목한 질문은 그 주체가 주격·소유격 조사를 달고 나온다.**

```
브래드 피트가 나온 …       지목함     → 못 찾으면 전제 오류가 맞다
봉준호의 영화 …            지목함
제주도를 배경으로 만든 …    지목 아님  → 키워드로 찾아본다
제주도 배경 영화 …          지목 아님
```

"홍길동이 나온 영화" · "마릴린 먼로가 나온 영화" 는 여전히 전제 오류로 막는다.

### 숫자를 말하는 곳과 만드는 곳

화면 첫 줄에 "한국 영화 1,018편" 이 **손으로 적혀** 있었다. 수집을 넓힌 뒤에도 그대로 떠
있었고, 거절 문구에도 같은 숫자가 박혀 있었다. 이제 `build-graph` 가 `stats.json` 을 만들고
화면과 문구가 거기서 읽는다. 사소해 보이지만 **사용자가 보는 유일한 규모 정보**였다.

### 안 하기 — 이쪽이 더 어려웠다

**BM25 는 어떤 질문에도 상위 N 개를 돌려준다.** "김치찌개 끓이는 법" 에도 영화 10편이
나온다. 즉 **"근거를 못 찾았다" 는 상태가 사실상 생기지 않는다.**

점수 문턱으로 자르려 했지만 실패했다. 실측해 보니 **범위 밖 질문의 점수가 범위 안
구어체 질문보다 높은 경우**가 있었다 — 두 분포가 겹쳐서 어디를 잘라도 한쪽이 샌다.

그래서 방향을 뒤집었다. 점수가 낮으면 거절하는 대신,
**이 도메인에 속한다는 증거가 있을 때만 답한다** (`domainSignal`).
말뭉치에 실제로 있는 제목 · 인물 · 배역 · 장르 중 하나라도 질문이 짚어야 한다.

여기에 **전제 검사**를 겹쳤다. 증거를 찾아본 뒤 "그런 조합이 없다" 를 확인하면,
모른다가 아니라 **"찾아봤는데 사실이 아니다"** 라고 말한다. 둘은 사용자에게 주는
정보의 양이 다르다.

### 근거는 완벽한데 답이 틀렸다

평가셋이 재는 것은 재현율뿐이었다. 그래서 이런 일이 숫자에 안 잡혔다 —

```
"황정민 배우가 나온 영화"      → 호프·곡성·서울의 봄·신세계…   맞다
"황정민이 출연한 영화"         → "확인되지 않습니다"           틀렸다
                                근거 12편은 세 번 다 똑같았다
```

그래서 답변을 채점하는 층을 만들었다. 만들자마자 **근거가 완벽한 문항 22건이 틀려 있었다**
(97/119, 82%). 열어 보니 셋 다 **탐색이 아니라 근거를 적는 방식**의 문제였다.

**① 연도에 '개봉' 을 안 적었다 (9문항)**
근거 줄이 `《기생충》 (2019)` 이었다. 모델은 그 괄호 숫자를 개봉 연도로 읽지 못하고
"근거에 명시되어 있지 않습니다" 라고 거절했다. 재현율은 `release 9/9` 만점이었다.
`(2019년 개봉)` 으로 바꾸니 붙었다. **데이터가 있는 것과 읽을 수 있게 적힌 것은 다르다.**

**② 제작진의 역할을 안 적었다 (2문항)**
`- 나홍진 (출연 아님, 제작진)` — 감독인지 각본인지 알 수 없다. 그래서
"《추격자》와 《황해》의 공통 감독은?" 에 **바로 윗줄에 나홍진이 적혀 있는데도**
"근거에 감독 정보가 없습니다" 라고 답했다. 그래프에는 DIRECTED 엣지가 분명히 있다.
실제 역할을 엣지에서 뽑아 `(감독·각본)` 으로 적는다.

**③ 이씨를 `Yi` 로 적으면 안 맞았다**
`이순신 ↔ Admiral Yi Sun-Shin` 이 어긋나 《명량》 근거에 **배우가 한 명도 안 실렸다.**
`Lee` 는 처리하는 규칙이 있었고 `Yi` 는 없었다 — 말뭉치 실측으로 **Lee 877마디 · Yi 171마디**다.

같은 뿌리로 하나 더 나왔다. **영(yeong)을 `Young` 으로 적은 것도 안 맞았다.**
영 단독 마디 2,093개가 `young` 1,517 · `yeong` 309 · `yong` 267 세 갈래인데
표기법(yeong)만 맞고 있었다. `ou→u` 규칙을 넣어 앞의 둘을 붙였다
(`yong` 267개는 **용(yong)과 충돌해서** 두었다 — 알면서 두는 선이다).

셋을 고쳐 **108/119 (91%)** 가 됐다. 그동안 재현율은 104/107·홀드아웃 63/66 에서
한 칸도 안 움직였다 — **두 층이 서로 다른 것을 재고 있다는 증거다.**

**④ 근거에 출연진이 없었다**
가장 큰 구멍은 마지막에 나왔다. 줄거리에는 배우도 배역도 안 적혀 있는데
근거의 작품 줄이 `제목 · 장르 · 평점 · 줄거리` 뿐이었다. 그래서 《극한직업》이
근거에 들어와 있는데도 **"류승룡 이름 자체가 근거에 없습니다"** 라고 답했고,
"펩시를 연기한 배우가 정 마담으로 나온 영화" 처럼 질문이 준 두 번째 조건도
확인할 수 없었다. 감독·각본과 주연 몇 명을 배역명과 함께 싣는다.

  《타짜》 (2006년 개봉) · 범죄/코미디 · 평점 6.9
      감독 최동훈 · 각본 최동훈 · 출연 조승우(Go-ni 역) · 김혜수(Madam Jeong 역) …

**토큰과의 교환이다.** 근거 블록 평균이 3,167자가 됐고 그중 **크레딧 줄이 25%** 다.
그래서 채점표가 근거 크기를 같이 찍는다 — 정확도만 보면 이 교환을 판단할 수 없다.
한 작품에 30명이 붙어 있으므로 감독·각본과 주연을 합쳐 **5명까지만** 싣는다.

    character 17/22 → **22/22**   bridge 10/12 → **12/12**   user-v1 16/20 → **20/20**

**그런데 이 변경이 두 자리를 망가뜨렸고, 그것도 같은 채점표가 잡았다.**

- `최종병기 활·명량·한산에 모두 출연한 배우는?` 의 답은 조단역 **김구택**이다.
  코드가 계산해 둔 교집합이 근거 맨 위에 있는데, 모델이 새로 생긴 작품별
  **주연 목록을 눈으로 대조해** 다시 고르려 들었다. 주연 5명만 실리므로
  거기에 김구택은 없다. **근거를 더 준 것이 답을 가렸다.**
  → "교집합 블록이 코드가 전수로 계산한 답이다. 작품별 목록으로 다시 고르지 마라"
- `괴물에 나온 배우들` 에 고레에다의 2023년작 출연진을 답했다. 동명이작 둘이
  근거에 있는데 양쪽 크레딧이 다 실린 탓이다. 출연진 질문은 위쪽
  [출연·제작진] 블록이 답이므로 **작품별 크레딧을 싣지 않는다.**

여기까지 **116/123 (94%)**. 남은 7건은 전부 수집 문제였다 — 개봉 날짜 5건, 수상 누락 2건.
답변 층에서 고칠 것은 남아 있지 않았다. **그래서 수집으로 내려갔다** (→ 다음 절).

채점 규칙 자체가 틀린 것도 하나 잡았다. "김혜수는 타짜·도둑들·암살에 모두 출연했다"
같은 **틀린 주장은 전제 오류로 막히는 것이 정답**인데, 처음엔 그걸 '답변 없음 = 틀림'
으로 세어 6문항을 거짓으로 깎았다. **채점이 틀리면 고칠 필요 없는 것을 고치게 된다.**

비용은 캐시로 막는다. 키가 (모델 · 시스템 프롬프트 · 근거 블록) 이라
검색이나 프롬프트가 바뀐 문항만 다시 부른다 — 채점 규칙만 고칠 때는 0원이다.

### 답변 층을 다 고치자 수집이 드러났다

남은 7건은 **답변을 어떻게 적는가**의 문제가 아니었다. 적을 것이 없었다.
셋 다 수집에서 버려지거나 안 받아온 것이고, 셋 다 **원래 있던 데이터**였다.

**① 개봉일을 연도로 깎아서 저장했다 (5문항)**
`"《타짜》의 국내 개봉일은?"` 에 "근거에 명시되어 있지 않습니다" 라고 거절했다.
TMDB 는 `release_date: "2006-09-28"` 을 준다. `build-graph.ts` 가 그것을
`Number(release_date.slice(0,4))` 로 **연도만 남기고 버리고 있었다.**
앞 절에서 `(2019년 개봉)` 으로 적는 것까지 고쳤는데, 정작 날짜 자체가 없었다.

```
year: 2006                      → "개봉일은?" 에 답이 안 된다
releaseDate: "2006-09-28"       → (2006년 9월 28일 개봉)
```

**② 수상 기록을 정렬 없이 앞에서 잘랐다**
`"송강호가 출연한 영화 중 칸 황금종려상을 받은 작품은?"` 에 "확인되지 않습니다".
《기생충》의 수상 기록에는 황금종려상도 아카데미 작품상도 **들어 있었다.**
그런데 근거에는 앞 3개만 실렸고, 그 셋이 하필
`아카데미 각본상 · 아카데미 감독상 · Gilde Film Price` 였다.
**Gilde Film Price 는 싣고 황금종려상은 버린 것이다.**

자르는 것 자체는 필요하다 — 한 편에 최대 22개가 붙어 있다. 틀린 것은 **정렬 없이
앞에서 자른 것**이다. 질문이 가리킨 상을 먼저 싣는다. 무엇을 묻는지는 코드가 글자로
확인할 수 있고, 거기서는 틀릴 일이 없다.

**③ 위키데이터 질의가 배우만 보고 있었다**
인물 수상 질의에 동명이인을 거르려고 직업 필터를 뒀는데, 그 목록이 **배우(Q33999)
하나뿐**이었다. 그래서 감독과 각본가가 통째로 빠졌다 — 봉준호의 황금종려상도,
아카데미 감독상도 우리 데이터에 **없었다.** 감독·각본가를 넣고 다시 받았다.

| 인물 수상 | 1,079명 5,288건 | **1,211명 6,004건** |
| 이창동 | 없음 | 3건 |
| 봉준호 | 없음 | 7건 (황금종려상·아카데미 감독상·작품상…) |

셋을 고치자 답변 층 손실이 **7 → 1**, 근거가 답을 담고 있을 때의 정확도가
94% → **99%** 가 됐다. 재현율은 또 **한 칸도 움직이지 않았다** —
세 번째다. 재는 층이 다르면 고쳐도 그 숫자는 반응하지 않는다.

#### 그리고 한 글자 제목은 씨앗이 된 적이 없다

위 ③을 확인하다 근거 블록을 눈으로 보고 알았다. `"이창동 감독이 《시》로…"` 의
근거에 **《시》가 한 편도 없었다.** 그래프에는 `이창동 ─DIRECTED─▶ 시` 가 분명히 있다.

제목 대조의 `m.title.length >= 2` 가 **한 글자 제목 36편**을 후보에서 통째로 빼고
있었다 — 시·콜·잠·섬·업·카·놉·씽…

그렇다고 가드를 풀 수는 없다. 실측하면 평가셋 152문항에서 글자 `시` 는 **18문항**,
`수` 는 **19문항**에 그냥 들어 있다. 대부분 제목이 아니라 남의 낱말 조각이다.

그래서 **괄호가 있을 때만** 연다 (`《시》`·`〈시〉`·`'시'`·`"시"`).
사람이 한 글자 제목을 말할 때는 괄호를 친다 — 안 치면 그 글자가 제목인지 낱말인지
**사람도 구분하지 못하기 때문**이다. 이 규칙으로 걸리는 문항은 152개 중 1개,
오탐은 0이다. 재현율도 그대로였다.

이 수정은 **어떤 숫자도 올리지 않았다.** h047 은 위키데이터에 그 상이 없어 여전히
답할 수 없다. 그래도 고친 이유는 `"《시》의 감독은?"` 이 지금까지 엉뚱한 작품
열 편을 내놓고 있었기 때문이다. **평가셋에 없는 고장도 고장이다.**

### 재지 않던 것을 재니 평가셋이 또 틀렸다

`《도둑들》과 《암살》에 모두 출연한 배우는?` 에 시스템이 **전지현**이라 답했고 오답으로
집계됐다. TMDB 크레딧을 전수로 보니 전지현은 **두 편 모두에 나온다.** 게다가 정답에
적힌 김혜수는 《암살》에 나오지 않는다.

**기억은 이 프로젝트에서 네 번 다 틀렸다.**

### 시스템이 평가셋의 오류를 찾아냈다

지금까지 평가셋의 오류는 **사람이 의심해서** 찾았다. 이번엔 순서가 반대였다.

답변 채점에 남은 실패 9건을 하나씩 열어 보다가 이것을 봤다 —

```
h010  "최민식과 황정민이 함께 출연한 영화는?"
      정답    《남산의 부장들》
      시스템  신세계, 쉬리, 끝과 시작      ← 오답으로 집계됐다
```

그래프에서 전수로 확인했다. **《남산의 부장들》 전체 크레딧 30명**은
이병헌·이성민·곽도원·이희준… 이고 **최민식도 황정민도 없다.**
두 사람의 공통 출연작은 시스템이 말한 셋이 전부다. **정답이 틀렸다.**

문항에는 오류가 셋 있었다.

| 칸 | 적혀 있던 것 | 실제 |
|---|---|---|
| `answer` | 《남산의 부장들》 | 신세계·쉬리·끝과 시작 |
| `kind` | `intersect-person` (답이 사람) | `intersect-movie` (답이 작품) |
| `needPerson` | `"남산의"` | (없음) |

`kind` 가 틀려 있어서 채점기는 **'남산의' 라는 이름의 사람**을 찾고 있었다.
그리고 `needMovies` 가 비어 있어서 **재현율 평가는 이 문항을 아예 채점하지 않았다** —
`scored` 가 `need.length` 로 거르기 때문이다. 한 문항이 세 군데에서 조용히 빠져 있었다.

함께 고친 것이 하나 더 있다.

```
h046  "《올드보이》가 2004년 칸 영화제에서 받은 상은?"
      정답    심사위원대상
      시스템  그랑프리                     ← 오답으로 집계됐다
```

칸 Grand Prix 의 한국어 표기가 둘이다. **같은 상이다.** 표기가 달라서 틀렸다고 세면
재는 것이 정확도가 아니라 **어휘 일치**가 된다. 그래서 `accept` 칸을 뒀다 —
정답을 **늘리는** 칸이 아니라 **같은 답의 다른 표기**만 담는 칸이다.

둘을 바로잡은 결과:

| | 전 | 후 |
|---|---|---|
| 재현율 | 104/107 (97%) | **105/108 (97%)** |
| 답변 채점 | 123/132 (93%) | **125/132 (95%)** |
| 근거에 답 있을 때 | 123/124 | **125/126 (99%)** |

(그 뒤 동명이작을 고쳐 **126** 이 됐다 → [아래](#고를-근거가-질문에-없으면-고르지-않는다))

**LLM 호출은 0회였다.** 캐시 키가 (모델 · 시스템 프롬프트 · 근거 블록) 이라,
코드가 한 줄도 안 바뀌었으면 같은 답을 다시 채점만 한다. 숫자가 올라간 것이
**시스템이 좋아져서가 아니라 채점이 정확해져서**라는 증거가 그것이다.

`intersect-movie` 가 18→19 가 되면서 BM25 는 **0/19** 가 됐다. 한 문항이 늘어도
BM25 는 한 칸도 못 얻는다 — 줄거리에 배우 이름이 없다는 것이 성능이 아니라
**원리**이기 때문이다.

### 손실이 아닌 칸이라고 안 보이게 뒀다

답변 채점의 네 칸 중 **"근거에 답 없음 × 답변 틀림"** 은 이 층의 손실이 아니다.
근거에 없는 것을 못 말한 것은 답변 층의 잘못이 아니기 때문이다.

그래서 **숫자만 찍고 목록은 안 찍었다.** 손실이 아니니까.

그 결과 그 칸 안에 무엇이 들어 있는지 보려면 매번 `--show` 로 132문항 전문을
훑어야 했다. 실제로 그렇게 훑다가 **평가셋의 정답 오류**를 발견했다
(→ [바로 위](#시스템이-평가셋의-오류를-찾아냈다)). 손실이 아닌 칸이라고 안 보이게 두면,
**그 안에 섞인 다른 종류의 고장도 같이 안 보인다.**

그래서 목록을 찍는다. 그리고 한 줄에 **어디서 잃었는지**까지 적는다 —
기대한 작품이 말뭉치에 아예 없는 것과, 말뭉치에 있는데 근거로 못 데려온 것은
**고칠 자리가 다르다.** 앞은 수집(`fetch`), 뒤는 탐색(`route`/`graph`)이다.

찍자마자 나온 것:

```
[h060] 박해일이 세종대왕을 연기한 영화는?
  진단  말뭉치에 **있다** (《나랏말싸미》) — 데려오지 못한 것이다 → 탐색
```

README 의 '아직 안 된 것' 에는 **《나랏말싸미》는 투표가 모자라 말뭉치 밖**이라고
적혀 있었다. 말뭉치를 1,721 → 3,072편으로 넓히면서 들어왔는데(투표 18),
**그때 그 문장을 고치지 않았다.** 한 줄 찍었더니 낡은 서술이 바로 드러났다.

여섯 건 중 **넷이 탐색 문제**였다. 수집 탓이라고 적어 둔 것들이다.

진단은 `needMovies` 가 아니라 **`expected` 로 낸다.** `needMovies` 는 비어 있을 수
있고(h080 이 그랬다 — 답이 작품인데 그 칸이 비어 있었다), 비어 있으면 진단이
조용히 틀린다. 재는 대상은 **유형표가 아니라 그 문항의 답**이다.

이 변경으로 **어떤 숫자도 움직이지 않았다.** LLM 호출도 0회다.
리포트가 한 칸 더 보이게 됐을 뿐이다. 그게 목적이다 —
**재지 않은 것은 고장 나 있어도 드러나지 않는다.**

### 고를 근거가 질문에 없으면 고르지 않는다

```
"괴물에 나온 배우들 알려줘"
  → 안도 사쿠라, 쿠로카와 소야, 히이라기 히나타…
```

말뭉치에 《괴물》이 둘 있다.

| | 감독 | 투표 | 인기 |
|---|---|---|---|
| 괴물 (2006) | 봉준호 | **3,239** | 7.9 |
| 괴물 (2023) | 고레에다 히로카즈 | 957 | **13.0** |

`titlesIn(question, g)[0]` 이 한 편을 골랐고, 그 순서를 정한 것이 **인기**였다.
인기는 최근작에 유리한 지표라 2023 이 이겼다.

**투표수로 바꾸면 되는 문제가 아니다.** 실측했다 — 동명이작 31개 중 한국·외국이
섞인 것이 12개다. 그 12개에서 외국 작품이 이기는 수는

| 정렬 기준 | 외국이 이김 |
|---|---|
| 인기 (현재) | 9 / 12 |
| 투표수로 바꾸면 | **9 / 12** |

**똑같이 9개다.** 뒤집히는 것은 《괴물》과 《남편들》 둘뿐이고, 서로 자리만 바꾼다.
《인터뷰》(2014, 투표 6,373) 는 《인터뷰》(2000, 투표 10) 를 어느 기준으로도 이긴다.

애초에 **고를 근거가 질문에 없다.** 사람이 그냥 "괴물" 이라고 했으면 **사람도**
어느 쪽인지 모른다. 그런데 코드는 하나를 골라 놓고, 어느 쪽을 골랐는지 말하지 않았다.

그래서 고르지 않는다. 둘 다 싣고 **어느 작품인지 밝힌다.**

```
[출연·제작진] — 같은 제목의 작품이 여럿이라 작품별로 적는다
  《괴물》 (2006) · 감독 봉준호
  - 송강호 (출연, Park Gang-du 역)
  …
  《괴물》 (2023) · 감독 고레에다 히로카즈
  - 안도 사쿠라 (출연, Saori Mugino 역)
```

모델도 그대로 나눠서 답한다 — *"《괴물》(2006) 출연 배우는 송강호… 《괴물》(2023)
출연 배우는 안도 사쿠라…"*. 이 프로젝트가 **답을 지어내지 않는다**고 한 것과 같은
자리다. 모르면 모른다고 하고, 둘이면 둘이라고 한다.

세 가지를 같이 지켰다.

- **한 편뿐이면 예전 그대로다.** 작품 꼬리표는 동명이작일 때만 붙어서 화면이 조용하다.
- **근거가 부풀지 않는다.** 여러 편이면 한 편당 줄 수를 25 → 12 로 줄인다.
  실측 — 근거 평균 3,285자 → **3,287자**.
- **`titlesIn` 자체는 안 건드렸다.** 거기서 동명이작을 둘 다 내보내면 전제 검사가
  `"《괴물》 《괴물》 에 모두 출연한 배우는 없습니다"` 로 오작동한다
  (`titles.length >= 2` 를 본다). 고칠 자리는 **고르는 곳**이지 찾는 곳이 아니었다.

순서는 **한국 작품 먼저**, 그다음 투표수로 못 박았다. 배열 순서에 기대면 수집
순서가 바뀔 때 조용히 뒤집힌다. 한국 영화를 앞에 두는 것은 외국 작품이 인물을 따라
1홉으로 들어온 **다리**이기 때문이다.

`cast` 4/5 → **5/5**, 답변 채점 125 → **126**. 재현율은 또 안 움직였다.

### 전제 검사를 하나 더 만들려다 접었다

`g4` 목록을 찍기 시작하자 h060 이 **탐색 문제**로 분류돼 나왔다.
《나랏말싸미》는 말뭉치에 있는데(2019, 투표 18) 근거로 못 데려온다는 것이다.

열어 보니 그게 아니었다.

```
《나랏말싸미》(2019) 크레딧
  송강호  as "King Sejong"      ← 세종대왕은 이쪽이다
  박해일  as "Monk Shin-mi"     ← 신미 스님
```

박해일의 **배역 32개를 전수로** 봐도 세종이 없다 (한산=이순신, 남한산성=인조).
말뭉치 전체에서 세종 역은 유장영·한석규·송강호 셋뿐이다.
**질문의 전제가 사실이 아니다** — w15~w18 과 같은 `no-answer` 다.
여섯 번째 정답 오류이고, 이번에도 시스템이 먼저 맞았다("확인되지 않습니다").

문항을 바로잡자 **숫자가 하나 내려갔다.** 전제 오류 판별이 4/4 → **4/5** 다.
h060 이 `no-answer` 로 들어오면서, **이 전제 오류를 코드가 못 잡는다는 사실**이
비로소 채점표에 나타난 것이다. 올바르게 분류할수록 약점이 드러난다.

#### 배역명에서 경칭을 뗀다

먼저 왜 못 찾았는지부터 봤다.

```
nameMatches("세종",     "King Sejong")  →  true
nameMatches("세종대왕", "King Sejong")  →  false
```

사람은 역사 인물을 **경칭과 함께** 부르는데 TMDB 는 그러지 않는다. 조사만 한두 글자
떼는 기존 규칙으로는 `세종대왕을 → 세종대왕 → 세종대` 까지밖에 못 간다.
경칭 목록(대왕·장군·왕자·공주·스님…)을 떼는 규칙을 넣었다.

위험을 먼저 쟀다 — 평가셋 152문항 전체에서 경칭을 떼어 **새로 생기는 후보는 1개**,
오탐 0이다. 넣고 나서 `character` 22/22 가 유지되는 것도 확인했다.

#### 못 고친 것 — 전제 검사는 만들면 안 되는 것이었다

그다음이 본론이었다. **"X 가 Y 를 연기한 영화"** 에서 Y 를 연기한 사람이 있는데
그게 X 가 아니면 전제 오류다 — 규칙은 명확해 보였다.

**코드에 넣기 전에 152문항 전체에 돌려 봤다.**

```
발동 15문항 / 152 — 그중 참인 것은 1개
```

| | |
|---|---|
| 맞게 막은 것 | h060 **1개** |
| **잘못 막았을 것** | **14개** |

```
[h032] 《올드보이》에서 오대수를 연기한 배우가 출연한 김지운 감독 영화는?
   지목 인물: 김지운(감독) · 오대수를 연기한 사람: 최민식
   → "김지운은 오대수를 연기한 적이 없습니다" 로 막았을 것이다
```

두 가지가 겹친다. ① 이런 질문이 지목하는 인물은 **배우가 아니라 감독**인 경우가
많다. ② `연기상`·`배우는`·`무엇인가` 같은 잡음이 로마자 배역명에 우연히 걸린다
(`전도연이 《밀양》으로 받은 칸 연기상은?` 이 장수진《하모니》에 걸렸다).

**그래서 넣지 않았다.** 잘못된 "전제가 사실이 아닙니다" 는 거절보다 나쁘다 —
거절은 "모른다" 지만 전제 오류는 **"찾아본 결과 사실이 아니다"** 라는 더 강한
주장이기 때문이다. 14번 틀릴 주장을 1번 맞히자고 넣을 수는 없다.

이 프로젝트에서 **고치지 않기로 한 판단을 실측으로 내린 첫 번째 자리**다.
쓰기 전에 152문항에 돌려 보지 않았다면, 14개가 깨진 뒤에야 알았을 것이다.

### 한국 영화 내비게이터인데 장르 색인에 한국 영화가 없었다

```
"역대 **한국 영화** 흥행 상위권 작품 중, 저승 세계를 소재로 한 판타지 영화는?"
  → 미니언즈 & 몬스터즈, 퍼피 구조대, 슈퍼 마리오 갤럭시 …
```

두 겹이었다.

**① 조건 낱말이 질문의 틀로 채워졌다.**

코드가 근거 본문에서 조건을 직접 세어 모델에게 건네는 블록이 있다. 그 조건 낱말이
`역대 · 한국 · 흥행 · 상위권 · 저승` 으로 잡혔다. 다섯 칸 중 넷을 **질문의 틀**이
차지하고 정작 `판타지` 는 잘려 나갔다. 그러고는 이렇게 답했다 —
*"역대, 흥행, 상위권 조건은 충족하지 않습니다."* **줄거리에 '흥행' 이라고 적힌
영화는 세상에 없다.**

수상 기록에서 이미 한 번 고친 것과 같은 결함이다. 자르는 것이 아니라
**정렬 없이 앞에서 자르는 것**이 틀렸다.

흔한말 목록을 실측으로 채웠다 — 평가셋 152문항에서 두 문항 이상에 반복되는 틀
(`무엇인가요` 19회, `국내` 12회, `언제인가요` 9회, `개봉일` 7회, `한국` 6회,
`흥행` 5회 …). 반대로 기생충·독일·기자·가족·아가씨처럼 **내용을 가리키는 것은
남겼다.** 장르도 대조 대상에 넣었다 — `판타지` 는 줄거리가 아니라 **장르 칸**에 있고,
모델은 근거에서 그것을 보는데 코드가 안 세면 둘이 어긋난다.

**이 수정만으로는 숫자가 하나도 안 움직였다.** 조건은 바로잡혔는데 정답이 여전히
근거에 없었기 때문이다. 그래서 더 내려갔다.

**② 장르 색인이 한국 영화를 통째로 버리고 있었다.**

```
판타지 장르 — 말뭉치 251편 (한국 105편)
  색인 30칸  =  전부 외국 애니메이션
  한국 영화  =  **0편**
```

`build-graph.ts` 가 장르당 30편을 **인기순으로** 잘랐다. TMDB 인기 지표에서 외국
애니메이션은 한국 영화를 압도한다. 한 줄로 세워 자르면 **다리가 본체를 덮는다** —
외국 작품은 인물을 따라 1홉으로 들어온 다리이지 이 질문의 후보가 아닌데도.

한국 30 + 외국 15 로 나눠 담았다. 색인이 30 → 45칸이 됐다.

```
판타지 색인 45편 · 한국 30편
  → 전지적 독자 시점, 외계+인 1부, **신과함께-죄와 벌**, …
```

씨앗 찾기에서도 질문이 **한국 영화라고 못 박았으면 그 조건을 지킨다**
(`/한국|국내/` 가 있으면 한국 작품만 본다). 코드가 질문에 적힌 조건을 버리고 있었다.

`release` 9/10 → **10/10**, 답변 채점 126 → **127/131 (97%)**.
재현율 105/107 은 이번에도 안 움직였다 — 이 문항은 `needMovies` 가 비어 있어
재현율이 애초에 채점하지 않는다. **두 층을 따로 재지 않았다면 이 고장은 끝까지
숫자에 안 잡혔을 것이다.**

### 수상 데이터의 절반을 조용히 버리고 있었다

```
"유아인이 《소리도 없이》로 받은 2020년 청룡영화상 연기상은?"
  → "근거에 없습니다"
```

데이터에는 **있었다.**

```json
{ "award": "청룡영화상 남우주연상", "year": null, "forTmdb": null, "forTitle": null }
```

`lib/ask.ts` 가 `.filter(x => x.forTitle)` 로 버리고 있었다. 수상 자격에 **작품이
달린 것만** 실은 것이다. 인물 수상은 "전도연이 《밀양》으로 칸 여우주연상" 처럼
작품을 거쳐 그래프와 이어지므로, 처음엔 그게 자연스러워 보였다.

실측하니 자연스럽지 않았다.

| | |
|---|---|
| 인물 수상 기록 | 6,040건 |
| **작품이 안 달린 것** | **3,442건 (57%)** |

위키데이터의 수상 서술에 수상 자격(P1686)이 늘 붙어 있지는 않다. **절반이 넘는다.**
예외를 거르는 규칙인 줄 알았는데 **본체를 거르고 있었다.**

그렇다고 다 실을 수는 없다 — 한 사람에게 최대 50건이 붙어 있다. 자르되
**질문이 가리킨 상을 먼저** 싣는다. 작품 수상에서 이미 쓴 규칙 그대로다.

그리고 수상작이 없으면 **없다고 적는다.**

```
- 유아인: 청룡영화상 남우주연상 — (어느 작품으로 받았는지는 데이터에 없다)
```

그냥 비워 두면 모델이 **질문에 나온 작품으로 받은 것**이라고 읽는다.
우리 데이터는 그렇게 말한 적이 없다. 실제로 모델은 이렇게 답했다 —

> 유아인이 《소리도 없이》로 받은 2020년 청룡영화상 연기상은 **확인되지 않습니다.**
> 다만, 유아인은 **청룡영화상 남우주연상**을 받은 적이 있습니다.

아는 것과 모르는 것을 나눠서 말한다. 이 프로젝트가 처음부터 지키려던 것이다.

`filmography` 14/15 → **15/15**, 답변 채점 127 → **128/131 (98%)**.

### 보여 주는 방식

- 3D 를 **별도 페이지에서 오른쪽 붙박이 패널로** — 답을 보며 그래프를 같이 봐야 한다
- 한 홉에 10개가 몰리면 겹쳐서 안 읽혔다 → **원둘레 배치**, 노드 수에 따라 반지름을 키운다
- 카메라가 2.6배 멀었다 → 화면 비율까지 넣어 다시 계산
- 확대하면 한글 라벨도 같이 커진다 (최대 2배)
- 노드를 고르면 **포스터를 모달로**
- 선은 정지한 그림이 아니라 **빛이 흘러간다** — 셰이더가 선의 각 픽셀을 직접 밝힌다

### 키는 사용자가 가져온다

배포를 염두에 두고 **설정 모달에서 OpenAI 키를 직접 넣게** 했다.
키는 그 브라우저에만 저장되고, 답변을 만들 때만 요청에 실린다.
**다만 요청이 이 사이트 서버를 거치므로 서버는 처리하는 동안 키를 본다** —
모달에 그대로 적어 뒀다. 숨기면 사용자가 판단할 수 없다.


## 실행

```bash
# Node 24+ (타입 스트리핑을 쓰므로 빌드 단계가 없다)
pnpm dev        # 웹 UI
pnpm ask "송강호와 이선균이 함께 출연한 영화는?"
pnpm test       # 순수 함수 단위 테스트 (LLM·데이터 없이 돈다)
pnpm eval       # 컨텍스트 재현율 — 그래프 vs BM25 (LLM 안 부른다, 비용 0)
pnpm eval:answer  # 답변 문장 채점 (LLM 을 부른다 — 캐시가 있어 안 바뀐 문항은 0원)

pnpm fetch      # TMDB 수집 (한 번, 40분)
pnpm awards     # 수상 — 위키데이터, 키 불필요
pnpm graph      # 그래프 구축
```

`.env.local` 에 두 개를 둔다.

```
TMDB_API_KEY=…     수집에만 쓴다. themoviedb.org 가입 → 설정 → API (무료)
OPENAI_API_KEY=…   답변 문장에만 쓴다. 없어도 근거는 그대로 나온다
```

`OPENAI_API_KEY` 는 **개발 중에만** 대체값으로 쓰인다. 배포 빌드에서는 무시하고,
화면의 설정에서 받은 키만 쓴다.

## 아직 안 된 것

정직하게 적는다.

- **테스트가 `lib/` 절반만 덮는다.** `romanize`·`graph`·`followup`·`route` 52개가
  있지만, 가장 크고 규칙이 많은 `route.ts`(44KB)는 제목 대조만 덮었다. 용언 어미
  필터·흔한말 목록은 아직 비어 있고, 지금까지 고친 결함도 대부분 거기서 났다.
- **위키데이터에 없는 상은 우리에게도 없다.** 이창동의 칸 각본상(《시》, 2010)이
  그렇다 — 이창동 항목의 수상 서술은 3건뿐이고, 영화 《시》 항목에는 **0건**이다.
  질의를 아무리 넓혀도 나오지 않는다(직업 필터를 완전히 빼고 확인했다).
  답변 채점에 남은 1건이 이것이고, **출처를 하나 더 붙이는 것 말고는 방법이 없다.**
- **한 글자 제목은 괄호를 쳐야 찾는다.** `"영화 시의 감독은?"` 은 못 찾고
  `"《시》의 감독은?"` 은 찾는다. 괄호 없이 열면 글자 `시` 가 18문항, `수` 가
  19문항에 걸려 오탐이 쏟아진다 — 형태소 분석기가 정공법이다.
- **화면은 눈으로만 확인했다.** 빌드·라우트·API 는 자동으로 돌지만
  3D 는 스크린샷을 보고 고쳤을 뿐, 회귀를 잡아 줄 장치가 없다.
- **줄거리 검색이 BM25 그대로다.** 남은 실패 3건 중 **2건이 여기다**
  (《기생충》을 "반지하 가족이 부유한 집에 차례로 취업하며…" 로 못 찾는다).
  글자가 겹쳐야 찾으므로 **말이 다른데 뜻이 같은 것**을 못 잇는다.
  벡터 검색이 정공법이다.
- **전제가 틀린 질문을 다 잡지는 못한다 (4/5).** "박해일이 세종대왕을 연기한
  영화는?" — 박해일은 그 역을 맡은 적이 없다(《나랏말싸미》의 세종은 송강호다).
  지금은 모델이 "확인되지 않습니다" 라고 **거절**해서 넘어간다. 옳은 답은
  **"찾아본 결과 사실이 아니다"** 인데, 그걸 코드로 판정하려다 실패했다 —
  시도와 실패의 기록은 [고도화](#전제-검사를-하나-더-만들려다-접었다)에 남겼다.
- **글자 바이그램이 복합어 가운데를 자른다.** `세종대왕 → 세종·종대·대왕` 에서
  '종대' 는 《강남 1970》의 김종대에 걸린다. 형태소 분석기가 정공법이다.
- **로마자 대조에 알고 있는 구멍이 둘 있다.** `영`을 `Yong` 으로 적은 267마디는
  용(龍)과 충돌해서 두었고, `김치 ↔ 김지` 는 치→chi→ji 라 마디 경계에 딱 맞아
  음절 경계 규칙으로 못 막는다. 둘 다 `test/romanize.test.ts` 에 한계로 박아 뒀다 —
  고치기로 하면 그 테스트가 먼저 뒤집힌다.
