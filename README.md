# 영화 네비게이터

한국 영화와 **그 인물이 참여한 외국 영화**를 하나의 그래프로 잇고,
인물이라는 다리를 건너 **근거와 함께** 답하는 GraphRAG 에이전트.

**▶ [movie-navigator.vercel.app](https://movie-navigator.vercel.app)**
— 답변 문장을 보려면 우측 상단 **설정**에서 OpenAI 키를 넣는다.
키 없이도 근거(작품·인물·다리)와 3D 는 그대로 나온다.

## 왜 만들었나

영화 질문에는 **한 문서만 읽어서는 답이 안 나오는 것**이 있다.

```
"송강호와 이선균이 함께 출연한 영화는?"

  《기생충》 줄거리:
    "전원 백수로 살 길 막막하지만 사이는 좋은 기택 가족…"
    → '송강호' 도 '이선균' 도 한 글자도 없다
```

**키워드·벡터 검색이 여기서 무너진다.** 배우 이름은 어느 줄거리에도 들어 있지 않다.
두 사람의 출연 목록을 각각 펼쳐 **겹치는 곳**을 봐야만 답이 나온다.

```
"기생충에서 기우를 연기한 배우가 출연한 좀비 영화는?"

  기생충 ──[기우]──▶ 최우식 ──출연──▶ 부산행
```

《부산행》 문서에 '기생충'은 없고, 《기생충》 문서에 '부산행'은 없다.
**최우식이라는 다리를 건너야만** 닿는다. 색인 시점에 그 다리를 놓아 두는 것이 이 프로젝트다.

## 측정을 믿을 수 있게 만든 것

**답이 맞는지 1초면 안다** — 이 프로젝트가 영화를 고른 이유다.
정답을 판단할 수 없는 도메인에서는 "재현율 90%" 같은 숫자를 만든 사람조차 검증할 수 없다.

그래서 평가셋 152문항 중 **143문항을 사용자가 직접 썼다.** 정답도 직접 매겼다.

실제로 그 덕에 잡힌 오류가 여럿이다 — 작성자가 기억으로 붙인 정답 100개 중 3개가
TMDB 전체 크레딧과 어긋났고(염정아는 《타짜》에 출연하지 않는다),
반대로 시스템이 맞았는데 정답이 틀려서 실패로 집계된 문항도 있었다.

> **기억은 이 프로젝트에서 세 번 다 틀렸다.** 작성자도, 나도 두 번.
> '없음' 판정은 전수를 봐야 성립한다 — 부분만 보고 "없다"고 하면
> 시스템이 맞을 때 틀렸다고 채점하게 된다.

## 측정 결과

**컨텍스트 재현율** — 정답에 필요한 작품을 근거로 데려왔는가.
LLM 없이 계산되므로 비용이 0이고, 여기서 못 데려온 것은 뒤에 어떤 모델을 붙여도 답에 못 쓴다.

### 홀드아웃 — 코드를 동결한 뒤 한 번만 채점한 숫자

| | 그래프 | BM25 |
|---|---|---|
| **동결 시점** | **79%** | 62% |
| 그 결과를 보고 고친 뒤 | 94% | 62% |
| 말뭉치를 1,721 → 3,072편으로 넓힌 뒤 | **95%** | 61% |

**79%가 일반화를 말할 수 있는 유일한 숫자다.** 뒤의 둘은 그 문항들을 보고 고친 것이다.
셋 다 남겨 둔다 — 격차 15%p 가 과적합의 크기다.

말뭉치를 두 배로 넓혔을 때 **한 번 89%까지 떨어졌다가** 95%로 올라왔다.
떨어진 다섯 문항을 열어 보니 말뭉치 크기가 원인인 것은 하나도 없었고,
전부 **원래 있던 결함이 후보가 늘면서 드러난 것**이었다 (→ [고도화](#고도화--부딪히고-고친-것들)).

### 유형별 — 그래프가 이기는 자리는 분명하다

| 유형 | 그래프 | BM25 | |
|---|---|---|---|
| **인물 교집합** (A와 B가 함께 나온 영화) | **18/18** | **0/18** | ★ |
| **다리 건너기** (배역 → 배우 → 다른 작품) | **11/11** | 1/11 | ★ |
| **수상** | 3/3 | 1/3 | ★ |
| 작품 교집합 (A·B·C에 모두 나온 배우) | 15/15 | 13/15 | |
| 배역명으로 배우 찾기 | 22/22 | 21/22 | |
| 개봉 연도 | 9/9 | 9/9 | |
| 인물 → 작품 | 14/14 | 7/14 | |
| **줄거리 내용으로 찾기** | **7/10** | **7/10** | ← 그래프가 도울 게 없다 |
| **전체** | **104/107** | **63/107** | |

**BM25 0/18 은 성능 차이가 아니라 원리적 불가능이다.** 줄거리에 배우 이름이 없으므로
어떤 텍스트 검색으로도 두 사람의 공통작을 구할 수 없다.

반대로 줄거리 질문("반지하 가족이 부유한 집에 차례로 취업하며…")은 답이 한 문서 안에
있으므로 그래프가 할 일이 없다. **이기는 자리와 지는 자리를 나눠서 재는 것**이 이 평가의 핵심이다.

### 답하지 않는 것도 기능이다

| | |
|---|---|
| 범위 밖 거절 (예매·스트리밍 위치) | **4/4** |
| 전제가 사실이 아닌 질문 | **4/4** |
| 참/거짓 판별 (틀린 전제를 섞어 놓은 문항) | **10/11** |

세 가지는 성격이 다르다.

```
⛔ 거절       "파묘 어디서 볼 수 있어?"
              → 이 도구가 다룰 범위가 아니다

🚫 전제 오류   "추격자·황해·곡성에 모두 출연한 배우는?"
              → 찾아봤더니 **그런 배우가 없다.** 겹치는 건 감독 나홍진뿐이다
```

거절은 "모른다"이고, 전제 오류는 **"찾아본 결과 사실이 아니다"** 라 더 강한 주장이다.
공통점은 하나 — **답을 지어내지 않는다.**

## 수집 범위 — 연대가 아니라 "선이 생기는가"

"초기 영화부터 다 넣으면?"을 실측했다.

| 구간 | 전체 | 투표 20+ |
|---|---|---|
| 1980년 이전 | 1,931편 | **9편** |
| 전체 | 14,546편 | 1,049편 |

이 측정이 **20표 문턱의 근거였는데, 옛 영화에만 맞는 근거였다.** 아래 고도화 참조.

옛 영화는 TMDB에 **제목만 있고 줄거리도 출연진도 없다.**
이 프로젝트는 관계로 답하므로 출연진이 없으면 **노드는 들어와도 선이 안 생긴다.**
연대로 자르는 대신 이 기준으로 잘랐다 — 《하녀》(1960)도 조건만 맞으면 들어온다.

```
① 한국 영화 2,212편     투표 5+ · 줄거리 있음 · 출연진 3명 이상
② 외국 영화   860편     ①의 인물을 따라 1홉 확장
③ 평가셋 지정 수집       인기와 무관하게 — 정답이 말뭉치에 없어서 틀리는 일을 막는다
```

처음엔 투표 20표로 잘랐다가 **5표 + 출연진 3명**으로 바꿨다. 인기가 아니라
**관계를 만들 사람이 있는가**가 진짜 기준이기 때문이다 (→ [고도화](#수집-기준을-인기에서-데이터로)).

②가 **국경을 넘는 다리**를 만든다. ①만 넣으면 "부산행 나온 배우가 마블에도 나왔다"가
성립하지 않는다.

**규모:** 영화 3,072 · 인물 27,282 · 엣지 63,530 · 수상 169편 473건 + 인물 1,098명 5,320건 · 한글 별칭 1,534명

## 구조

```
scripts/fetch-movies.ts   TMDB → data/raw.json
scripts/fetch-awards.ts   위키데이터 → data/awards.json   (TMDB 에 수상 정보가 없다)
scripts/build-graph.ts    → data/graph.json + 품질 보고서
scripts/evaluate.ts       그래프 vs BM25 (LLM 0회)
scripts/ask.ts            질문 하나를 터미널에서

lib/graph.ts     탐색 — 경로별 예산, 순수 함수
lib/route.ts     5갈래 라우팅 · 씨앗 찾기 · 도메인 게이트 · 전제 검사
lib/romanize.ts  한글 ↔ 로마자 배역명 대조
lib/followup.ts  이어지는 질문 — "그중에 상 받은 건?"
lib/answer.ts    답변 문장 생성 (유일하게 LLM 을 부르는 곳)
lib/ask.ts       질의 파이프라인 (LLM 호출 없음)
lib/bm25.ts      한국어 바이그램 BM25

app/             질문 · 작품 탐색기 · 지도 + 오른쪽 붙박이 3D · 설정(키 입력)
```

**관계 추출에 LLM을 쓰지 않는다.** 출연·연출은 TMDB 크레딧에 명시돼 있어 지어낼 여지가 없다.

### 배역명이 로마자로만 온다

TMDB는 `language=ko-KR`로 요청해도 배역명을 현지화하지 않는다
(배역명 4,022개 중 한글은 19개). 한글을 로마자로 바꿔 대조하되, **표기가 표준을 따르지 않는다:**

```
자성 → Ja-sung   (국어의 로마자 표기법이면 Ja-seong)
안   → Ahn       (표기법이면 An)
```

정확한 변환이 목적이 아니라 **같은 이름인지 판정**이 목적이므로, 양쪽을 같은 규칙으로
뭉갠 뒤 음절 경계에서 대조한다. **17/17 일치.**

## 답변 문장 — LLM 은 마지막에만

`lib/answer.ts` 가 **유일하게 LLM 을 호출하는 곳**이다 (OpenAI `gpt-4.1-mini`).
탐색·라우팅·조립에는 LLM 이 한 줄도 없다. 무엇을 근거로 데려왔는지를 모델 없이
검증할 수 있어야 하고, 그래서 평가가 **비용 0** 으로 돌아간다.

**2겹으로 막는다.**

```
코드 층     근거가 없거나 전제가 틀렸으면 호출 자체를 하지 않는다
            → 호출하지 않으면 지어낼 기회가 없다
프롬프트 층  "아래 근거에만 있는 사실을 쓰라. 없으면 없다고 하라.
            네가 따로 아는 영화 지식을 끌어오지 마라"
```

모델에 넘기는 근거는 **화면에 뜨는 것과 같은 내용**이다. 둘이 어긋나면 사용자가 검증할 수 없다.
답변은 근거 위에 두되 근거를 지우지 않는다 — 무엇을 보고 말했는지 확인할 수 있어야 한다.

## 이어지는 질문

```
"송강호가 나온 영화 알려줘"     → 기생충, 살인의 추억, 설국열차 …
"그중에 상 받은 건 어떤거야?"   → 《기생충》 (새로 찾지 않았다)
```

`그중 · 거기서 · 방금 · 위에서` 같은 말이 나오면 **직전 근거를 그대로 물려받아 거른다.**
수상 여부 · 국적 · 연도 · 평점 · 장르로 거를 수 있다.

LLM 에게 대화 이력을 주고 다시 찾게 할 수도 있었지만, 그러면 **검색 경로에 LLM 이 들어가**
이 프로젝트의 성질이 깨진다. 거를 조건을 못 찾으면 **이어붙이기를 포기하고 그 이유를 말한다** —
억지로 이으면 엉뚱한 답이 나오는데 사용자는 왜 그런지 알 수 없다.

## 화면

```
┌────────────────────────┬────────────────────────┐
│  질문 / 작품 탐색기 / 지도  │   3D (붙박이)           │
└────────────────────────┴────────────────────────┘
```

세 화면은 **서로 독립**이다. 서로를 링크하지 않고, 각자 **주제만** 3D에 넘긴다.
왼쪽에서 무엇을 보든 오른쪽이 따라 바뀐다.

3D의 Y축은 **홉 거리**다 — 질문에서 출발해 인물을 몇 번 건넜는가.
선 위에 뜨는 이름이 **다리의 정체**이고, 한국/외국은 색으로 갈린다.

## 고도화 — 부딪히고 고친 것들

처음부터 이렇게 생기지 않았다. **틀린 답이 하나 나올 때마다 원인을 한 층씩 거슬러 올라간
기록**이다. 증상 → 원인 → 조치 순으로 적는다.

### 수집 — 없는 것은 찾을 수 없다

검색을 아무리 고쳐도 **말뭉치에 없으면 답이 안 나온다.** 실패의 절반은 수집 쪽이었다.

| 증상 | 원인 | 조치 |
|---|---|---|
| "곡성에 나온 배우" 에 김윤석이 없었다 | 출연진을 **상위 10명**만 받았다 | 30명으로. 답이 주연에만 있지 않다 |
| "전도연과 설경구가 함께 나온 영화" → 없다 | 《생일》(2019)이 말뭉치에 없었다 | 평가셋 작품은 **인기와 무관하게 지정 수집** |
| 한국 배우의 외국 작품이 안 잡혔다 | 한국 영화만 수집했다 | 2편 이상 나온 인물 3,474명을 따라 1홉 확장 → 외국 703편 |
| 수상 질문에 답할 게 없었다 | **TMDB 에 수상 정보가 없다** | 위키데이터 SPARQL 로 별도 수집, TMDB ID 로 결합 |
| "상 받은 배우" 와 "상 받은 영화" 가 섞였다 | 작품 수상만 모았다 | 인물 수상을 따로 (996명 4,961건) |

평가셋 지정 수집은 순서가 중요하다. 인기순으로만 자르면 **평가가 검색 품질이 아니라
수집의 구멍을 재게 된다** — 못 맞힌 이유가 "탐색이 못 갔다" 인지 "애초에 없다" 인지
구별이 안 된다.

### 이름이 하나가 아니다 — 별칭

가장 오래 못 찾은 버그다.

```
"아이유가 나온 영화 알려줘"
  → "아이유가 나온 영화는 근거에 확인되지 않습니다"

  …그런데 화면 아래에는 아이유 출연작들이 떠 있었다.
```

**TMDB 의 인물명은 '이지은' 이다.** '아이유'는 `also_known_as` 에만 들어 있었다.
말뭉치에 2편 이상 있는 인물 3,474명의 별칭을 조회해 **514명분**을 채웠다.
마동석 = 돈 리, 이병헌 = Byung-hun Lee 도 같은 문제다.

그런데 별칭을 채우고도 처음엔 안 고쳐졌다. **인물을 대조하는 코드가 세 군데에
복사돼 있었기 때문이다** (`seedsFromPerson` · `seedsFromPersonAward` · `ask.ts`).
한 곳만 고치면 나머지 두 경로로 들어온 질문은 그대로 틀린다.

> 지금은 `peopleIn()` 한 곳에서만 사람을 찾는다.
> **아이유만 고쳐진 게 아니라 514명 전부, 그리고 모든 질문 경로에 적용된다.**
> "한 군데를 고쳤는데 증상이 그대로" 는 대개 같은 일이 여러 군데에서 벌어지고 있다는 뜻이다.

### 탐색 — 멀리 가는 것보다 안 나가는 게 어렵다

```
"송강호가 나온 영화 알려줘"
  답은 3편인데 화면에는 12편이 떴다
```

탐색이 씨앗에서 한 홉 더 나가 **송강호와 같이 나온 사람들의 다른 작품**까지 끌고 왔다.
"X 가 나온 영화" 의 답은 **정확히 X 의 작품**이다. 밖으로 나가면 답이 아니라 소음이다.

그래서 질문 갈래마다 **나갈 수 있는 예산을 따로 뒀다** (`ROUTE_PLAN`).
`filmography` · `cast` 는 예산이 **0** 이다 — 다리를 건너야 하는 질문과
건너면 안 되는 질문은 반대 방향으로 튜닝된다.

그 밖에 이 단계에서 추가된 것:

- **교집합 씨앗** — 두 사람을 각각 펼친 뒤 겹치는 곳에서 시작한다. BM25 가 0/18 인 자리
- **씨앗 사이 다리** — 결과들이 한 사람을 공유하면 그 선을 그린다. 화면에서 왜 같이 나왔는지 보인다
- **배역 → 배우 → 작품** 3단 경로
- **[이어지는 질문](#이어지는-질문)** — 직전 근거를 물려받아 거른다

### 로마자가 너무 잘 맞는다 — 용언이 이름으로 읽힌다

```
"호랑이가 나오고 포수와 대결하는 영화가 어떤거지?"
  → 씨앗에 《바람이 분다》·《경성학교》·《죠죠의 기묘한 모험》이 들어왔다
```

**`나오고` 가 배역명으로 읽혔다.**

```
나오고 → na·o·go
Naoko  → na·o·ko → na·o·go      (표기 보정용 k→g 규칙에 걸렸다)
```

`나오` 는 퍼지 없이도 `Nao`·`Naho` 와 글자 그대로 같다. 로마자 변환은 틀리지 않았다 —
**`나오다` 가 한국어에서 흔한 용언이라는 것**이 문제다.

앞서 만든 "네 편 이상에 걸치면 흔한 말" 규칙은 이걸 못 잡는다. `나오고` 는 2편뿐이다.
**걸러야 할 것이 빈도가 아니라 품사였다.** 둘을 넣었다.

1. **용언 어미로 끝나는 어절에서는 배역 후보를 뽑지 않는다.**
   이름으로 끝날 수 있는 꼬리(서·지·나·은)는 **일부러 뺐다** — 넣으면 은서·민지·유나·지은이
   전부 날아간다. 이름에 안 쓰이는 어미만 담는다.
2. **작품이 지목되지 않았다면, 질문이 배역을 묻고 있을 때만 전역으로 훑는다.**
   말뭉치에 배역명이 4,022개 있다. 두세 글자 덩어리를 전부와 대조하면 우연히 겹치는 것이
   거의 언제나 나오고, 그것이 **진짜 씨앗을 앞자리에서 밀어낸다.**

2번의 표지는 평가셋에 대고 맞췄다 — `character` 22문항 중 **21문항**이 걸린다
(나머지 하나는 제목 두 개가 지목된 감독 질문이라 작품 범위로 좁히는 분기로 간다).
`지역`·`역사`·`통역` 의 '역' 은 앞 글자를 보고 제외한다.

> 고친 뒤 평가셋 숫자는 **한 칸도 움직이지 않았다** (전체 103/107 · 홀드아웃 62/66).
> 답을 더 맞히는 변경이 아니라 **답이 아닌 것을 덜 데려오는 변경**이라 그렇다.
> 재현율만 보면 안 보이고, 화면을 봐야 보인다.

### 묻는 방식이 검색을 흐린다

```
"세종대왕에 대한 이야기가있는 영화 알려줘"
  → "세종대왕에 대한 이야기가 있는 영화는 근거에 없습니다"

  …말뭉치에는 《천문: 하늘에 묻는다》(2019)와 《신기전》(2008)이 있다.
```

BM25 순위를 열어 보니 천문이 **6위**였다. 씨앗은 상위 3개만 쓰므로 떨어졌다.

```
 1. 알파고    2. 무서운 이야기 2    3. 배트맨: 이어 원
 4. 라푼젤: 끝나지 않은 이야기      5. 오징어 게임… 이야기      6. 천문 ←
```

**'이야기' 가 제목에 '이야기' 가 든 작품들을 끌어올렸다.** IDF 가 흔한 말을 깎아 주지만,
**묻는 방식에서 온 말**까지는 깎지 못한다. 그래서 질문 쪽에서만 상투어를 걷어낸다
(알려줘·추천·영화·이야기·관련된·대한·나오는…). 색인에서는 빼지 않는다 —
《무서운 이야기》는 진짜 제목이다. 걷어내니 천문이 **1위**가 됐다.

함께, **확실한 단서(제목·인물·수상)가 하나도 없을 때만** 키워드 씨앗을 3 → 6개로 늘렸다.
그런 질문일수록 순위가 흔들리는데 상위 3개만 보는 것은 순위를 너무 믿는 것이다.

#### 못 고친 것 — 바이그램은 낱말 가운데를 자른다

```
세종대왕 → 세종 · 종대 · 대왕
  세종 → 천문 · 신기전          정확
  종대 → 강남 1970              김종대, 줄거리에 3회 — 그래서 1위였다
  대왕 → 신과함께(염라대왕) · 역린 · 툼 레이더
```

세 조각 중 **둘이 엉뚱하다.** 한국어 조사 문제(봉준호가 / 봉준호의)를 풀려고 글자
바이그램을 쓰는데, 그 대가로 복합어 가운데가 잘린다. 형태소 분석기를 붙이는 것이
정공법이고, 지금은 **알면서 감수하는 비용**으로 남겨 둔다.

### 수집 기준을 인기에서 데이터로

```
"제주도에 관련된 영화 중 민간인을 빨갱이로 죽인 사건을 다룬 영화가 뭐야?"
  → 《최후의 증인》(1980) 입니다           ← 지리산·6.25 영화다. 제주도가 아니다.
```

찾아야 할 답은 **《지슬: 끝나지 않은 세월 2》**(2013, 오멸) 였는데 말뭉치에 없었다.
TMDB 에 물어보니 **13표**여서 투표 20표 문턱에 잘려 있었다. 그런데 데이터는 멀쩡했다 —
줄거리 211자, 출연 21명, 감독, 포스터까지.

문턱의 근거는 "표가 적으면 정보가 부실하다" 였고, 그 측정은 **1980년 이전 영화로 한 것**이었다.
현대 독립영화에는 맞지 않는다. 한국 영화는 TMDB 투표 수가 전반적으로 낮아서,
《영웅》(2022)·《야구소녀》(2020)·《군산: 거위를 노래하다》(2018)가 **전부 19표**다.
인기로 자르면 작품이 아니라 **관객 수를 자르게 된다.**

그래서 기준을 바꿨다. 투표 수는 **비용을 줄이는 1차 거름망**으로 내리고(5표),
진짜 기준은 크레딧을 받아 본 뒤 **출연진이 3명 이상인가**로 뒀다.
관계로 답하는 도구이므로 그것이 실제로 필요한 조건이다.

| | 전 | 후 |
|---|---|---|
| 한국 영화 | 1,018편 | **2,212편** |
| 외국 영화 | 703편 | **860편** |
| 한글 별칭 | 514명 | **1,534명** |

**②-b 단계에서 걸러진 것은 2,303편 중 56편(2.4%)뿐이었다.** 즉 20표 문턱이 자르고 있던 것은
"데이터 없는 작품" 이 아니라 **그냥 덜 알려진 작품**이었다. 대리 지표를 직접 측정으로
바꾸자 드러났다.

### 말뭉치를 두 배로 키웠더니 점수가 떨어졌다

홀드아웃이 **94% → 89%** 로 내려갔다. "데이터를 줄일까" 가 먼저 떠올랐지만,
떨어진 다섯 문항을 전부 열어 보니 **말뭉치 크기가 원인인 것은 하나도 없었다.**

#### ① 흔한 말과 같은 이름 (3문항)

```
"현빈과 손예진이 함께 **주연을** 맡은 영화는?"
  peopleIn → 손예진 · 현빈 · **주연**        ← 이 이름의 인물이 실제로 있다
  교집합 세 사람 → 공통작 0 → "함께 나온 작품이 없습니다"
```

배역명에 쓰던 흔한말 목록을 인물 이름에도 적용했다. 같은 뿌리의 사고가 하나 더 있었다 —
별칭 '이선' 을 가진 작가가 "**이선**균이" 에 걸렸는데, 중복 제거를 **본명끼리** 하고 있어서
살아남았다(`"이선균".includes("이맹유")` 는 거짓이다). **실제로 걸린 글자**로 비교하게 고쳤다.

#### ② 확실한 단서가 BM25 를 막고 있었다 (1문항)

```
"독일 기자를 태운 택시기사가 **1980년** 광주로 향하는 영화는?"

BM25 순위      1위 《택시운전사》 42.79점
실제 씨앗      《1980》 · 《19》          ← BM25 는 호출조차 되지 않았다
```

'1980년' 이 《1980》(2024)이라는 **제목**에 걸렸고, 제목은 "확실한 단서" 라서
`findSeeds` 가 거기서 돌아가 버렸다. **검색은 이미 정답을 1위로 갖고 있었다.**

이 함정은 전에 한 번 겪고 배역 씨앗에 대해서만 고쳐 뒀던 것이다(《부산행》 사고).
**같은 함정의 다른 입구였다.** 이제 **어떤 씨앗도 BM25 를 막지 않는다** —
순서가 이미 우선순위를 표현하고, 넘치는 것은 근거 예산이 자른다.

#### ③ 질문이 준 두 번째 조건을 버리고 있었다 (2문항)

```
"《버닝》에서 종수를 연기한 배우가 **조태오로** 출연한 영화는?"    → 《베테랑》
"…광해군을 연기한 배우가 출연한 **김지운 감독** 영화는?"        → 《좋은 놈, 나쁜 놈, 이상한 놈》
```

배우는 맞게 찾아 놓고 그 사람의 작품을 **전부** 담았다. 유아인 16편에서 《베테랑》이
근거 예산(10편) 밖으로 밀렸다. **말뭉치가 커질수록 한 사람의 작품이 늘어 이 손실이 커진다** —
근거를 더 담는 것으로는 못 막고, 질문이 이미 준 조건을 쓰는 것이 맞다.
배역명과 감독으로 좁히게 하자 **다리 건너기가 11/11 로 처음 만점**이 됐다
(1,721편 시절에도 못 풀던 문항까지 풀렸다).

#### ④ 동명이작을 인기순으로 골랐다

```
"송강호는 《살인의 추억》, 《괴물》, 《기생충》에 모두 출연했다"  → 시스템: 아니다
```

《괴물》이 두 편이 됐다 — 봉준호(2006)와 고레에다(2023). 제목 대조가 **인기순으로**
2023년작을 골라서, 맞는 말이 거짓으로 채점됐다. 수상 결합에서 이미 겪고 TMDB ID 로
풀었던 문제가 이번엔 제목 매칭에서 나왔다.

고친 방식은 **고르지 않는 것**이다. 같은 제목을 묶어서 넘기고, 공통 인물이 나오는 조합을
쓰게 했다. **어느 《괴물》인지는 인기가 아니라 질문의 나머지가 정한다.**

#### 그래서

| | 1,721편 | 3,072편 (처음) | 3,072편 (고친 뒤) |
|---|---|---|---|
| 전체 | 103/107 | 98/107 | **104/107** |
| 홀드아웃 | 62/66 | 59/66 | **63/66** |
| 다리 건너기 | 10/11 | 8/11 | **11/11** |

> **큰 말뭉치는 더 어려운 시험이었고, 그 시험이 원래 있던 결함 네 개를 드러냈다.**
> 1,721편일 때의 96% 는 파이프가 더 좋아서가 아니라 함정을 덜 밟았기 때문이다.
> 데이터를 줄였다면 숫자는 돌아왔겠지만 **결함은 그대로 남았을 것이다.**

### 답이 아닌데 답이라고 한다 — 조건이 여럿일 때

```
질문   제주도 + 민간인 + 빨갱이
답변   "《최후의 증인》입니다"      ← '빨갱이' 만 맞다. 제주도는 줄거리에 없다.
```

"조건을 전부 확인하라" 고 프롬프트에 적어도 고쳐지지 않았다. 모델에게 **대조를 시키는 대신
대조 결과를 건네주는** 쪽으로 바꿨다 — 글자가 있는지 없는지는 코드가 틀릴 수 없다.

```
[조건 대조 — 코드가 근거 본문에서 직접 세어 본 것]
질문의 낱말: 제주도 · 민간인 · 빨갱이 · 죽인
**4개를 모두 담은 작품은 근거에 없다.** 가장 많이 맞은 것도 2개다.
- 《최후의 증인》 : 맞음 빨갱이·죽인 / 없음 제주도·민간인
```

처음엔 낱말마다 따로 찾게 했는데 그것은 틀린 설계였다 — '제주도' 가 《올레》에 있고
'빨갱이' 가 《최후의 증인》에 있다고 해서 **둘 다 가진 작품이 있는 것은 아니다.**
질문이 묻는 것은 결합이므로 **작품 단위로** 센다.

### 숫자를 말하는 곳과 만드는 곳

화면 첫 줄에 "한국 영화 1,018편" 이 **손으로 적혀** 있었다. 수집을 넓힌 뒤에도 그대로 떠
있었고, 거절 문구에도 같은 숫자가 박혀 있었다. 이제 `build-graph` 가 `stats.json` 을 만들고
화면과 문구가 거기서 읽는다. 사소해 보이지만 **사용자가 보는 유일한 규모 정보**였다.

### 안 하기 — 이쪽이 더 어려웠다

**BM25 는 어떤 질문에도 상위 N 개를 돌려준다.** "김치찌개 끓이는 법" 에도 영화 10편이
나온다. 즉 **"근거를 못 찾았다" 는 상태가 사실상 생기지 않는다.**

점수 문턱으로 자르려 했지만 실패했다. 실측해 보니 **범위 밖 질문의 점수가 범위 안
구어체 질문보다 높은 경우**가 있었다 — 두 분포가 겹쳐서 어디를 잘라도 한쪽이 샌다.

그래서 방향을 뒤집었다. 점수가 낮으면 거절하는 대신,
**이 도메인에 속한다는 증거가 있을 때만 답한다** (`domainSignal`).
말뭉치에 실제로 있는 제목 · 인물 · 배역 · 장르 중 하나라도 질문이 짚어야 한다.

여기에 **전제 검사**를 겹쳤다. 증거를 찾아본 뒤 "그런 조합이 없다" 를 확인하면,
모른다가 아니라 **"찾아봤는데 사실이 아니다"** 라고 말한다. 둘은 사용자에게 주는
정보의 양이 다르다.

### 보여 주는 방식

- 3D 를 **별도 페이지에서 오른쪽 붙박이 패널로** — 답을 보며 그래프를 같이 봐야 한다
- 한 홉에 10개가 몰리면 겹쳐서 안 읽혔다 → **원둘레 배치**, 노드 수에 따라 반지름을 키운다
- 카메라가 2.6배 멀었다 → 화면 비율까지 넣어 다시 계산
- 확대하면 한글 라벨도 같이 커진다 (최대 2배)
- 노드를 고르면 **포스터를 모달로**
- 선은 정지한 그림이 아니라 **빛이 흘러간다** — 셰이더가 선의 각 픽셀을 직접 밝힌다

### 키는 사용자가 가져온다

배포를 염두에 두고 **설정 모달에서 OpenAI 키를 직접 넣게** 했다.
키는 그 브라우저에만 저장되고, 답변을 만들 때만 요청에 실린다.
**다만 요청이 이 사이트 서버를 거치므로 서버는 처리하는 동안 키를 본다** —
모달에 그대로 적어 뒀다. 숨기면 사용자가 판단할 수 없다.


## 실행

```bash
# Node 24+ (타입 스트리핑을 쓰므로 빌드 단계가 없다)
pnpm dev        # 웹 UI
pnpm ask "송강호와 이선균이 함께 출연한 영화는?"
pnpm eval       # 그래프 vs BM25

pnpm fetch      # TMDB 수집 (한 번, 40분)
pnpm awards     # 수상 — 위키데이터, 키 불필요
pnpm graph      # 그래프 구축
```

`.env.local` 에 두 개를 둔다.

```
TMDB_API_KEY=…     수집에만 쓴다. themoviedb.org 가입 → 설정 → API (무료)
OPENAI_API_KEY=…   답변 문장에만 쓴다. 없어도 근거는 그대로 나온다
```

`OPENAI_API_KEY` 는 **개발 중에만** 대체값으로 쓰인다. 배포 빌드에서는 무시하고,
화면의 설정에서 받은 키만 쓴다.

## 아직 안 된 것

정직하게 적는다.

- **테스트가 없다.** `lib/romanize.ts`·`lib/graph.ts`·`lib/followup.ts`는 순수 함수라
  테스트하기 좋은데도 아직 안 썼다.
- **화면은 눈으로만 확인했다.** 빌드·라우트·API 는 자동으로 돌지만
  3D 는 스크린샷을 보고 고쳤을 뿐, 회귀를 잡아 줄 장치가 없다.
- **줄거리 검색이 BM25 그대로다.** 남은 실패 3건 중 2건이 여기다
  (《기생충》을 "반지하 가족이 부유한 집에 차례로 취업하며…" 로 못 찾는다).
  글자가 겹쳐야 찾으므로 **말이 다른데 뜻이 같은 것**을 못 잇는다.
  벡터 검색이 정공법이다.
- **여전히 수집에서 새는 것이 있다.** 《나랏말싸미》(2019)는 투표가 5표에도 못 미쳐
  아직 밖이다. 문턱을 더 내리면 들어오지만 API 호출이 몇 배로 늘어난다 —
  지금은 **알면서 두는 선**이다.
- **글자 바이그램이 복합어 가운데를 자른다.** `세종대왕 → 세종·종대·대왕` 에서
  '종대' 는 《강남 1970》의 김종대에 걸린다. 형태소 분석기가 정공법이다.
