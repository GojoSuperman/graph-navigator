# 영화 네비게이터

한국 영화와 **그 인물이 참여한 외국 영화**를 하나의 그래프로 잇고,
관계를 건너 걸으며 **근거와 함께** 답하는 GraphRAG 에이전트.

## 왜 만들었나

영화 질문에는 **한 문서만 읽어서는 답이 안 나오는 것**이 있다.

```
"부산행 나온 배우가 마블 영화에도 나왔다던데?"

  부산행 ──출연──▶ 마동석 ──출연──▶ 이터널스
```

**키워드·벡터 검색이 여기서 무너진다.** 《이터널스》 문서 어디에도
'부산행'이라는 말이 없고, 그 반대도 마찬가지다. 두 문서는 어휘가 겹치지 않는다.
**마동석이라는 다리를 건너야만** 닿는다.

색인 시점에 그 다리를 미리 놓아 두는 것이 이 프로젝트다.

> 이 구조는 선행 프로젝트 [law-navigator](../law-navigator)에서 가져왔다.
> 거기서는 다리가 **위임**이었다 — 법 제21조의 "대통령령으로 정하는 방법"이
> 시행령 제16조로 이어지는 자리. 도메인만 바뀌고 문제의 모양은 같다.

## 왜 영화로 바꿨나

선행 프로젝트는 잘 돌았지만 **만든 사람이 결과를 검증할 수 없었다.**
"제21조가 정답인가"를 판단하려면 법률 지식이 필요했고, 그래서 측정치를
전부 남의 말로 믿어야 했다.

영화는 다르다. **답이 맞는지 1초면 안다.** 평가셋을 직접 쓰고 직접 채점할 수 있다.
"재지 않은 것은 고장 나 있어도 100%로 보인다" — 선행 프로젝트에서 얻은 교훈을
적용하려면, 잴 수 있는 사람이 있어야 한다.

## 수집 범위 — "넓게"가 아니라 "이어지는 것만"

전 세계 영화를 다 넣으면 수십만 편이라 씨앗 찾기가 망가지고,
한국 영화만 넣으면 가장 좋은 질문(국경을 넘는 다리)이 사라진다.

```
① 한국 영화              인기·평점 상위, 줄거리 있는 것
② ①의 인물이 참여한 외국 영화   인물을 따라 1홉 확장
```

선행 프로젝트에서 "위임을 실제로 받는 고시만 골라 넣은" 것과 같은 원리다.

## 실행

```bash
# Node 24+ (타입 스트리핑을 쓰므로 빌드 단계가 없다)
pnpm fetch      # TMDB 수집 → data/raw.json
pnpm graph      # 그래프 구축 + 품질 보고서 → data/graph.json
pnpm eval       # 그래프 vs BM25 비교 (LLM 0회)
pnpm test
```

TMDB 키는 [themoviedb.org](https://www.themoviedb.org) 가입 후 설정 → API 에서
무료로 받는다. `.env.local`에 `TMDB_API_KEY=...`로 둔다.
