# 실패 정독 — 대표 5건

> 7.3단계 · 2026-09-21
> 루브릭 3은 *"실패 사례를 **직접 읽어** 색인·탐색·생성 중 어디서 깨졌는지 구분해
> 기록했는가"* 를 묻는다. 코드 판정표(`eval.json`)는 분포를 보여 주지만 **원인은
> 보여 주지 않는다.** 여기서는 손으로 읽는다.

## 층별 분포 — 코드 판정

```
둘 다 성공                        22/44
생성 (근거는 왔는데 답이 틀림)      17/44   ← 가장 큰 손실
탐색 (근거를 못 데려옴)              5/44
색인 (기대 문서가 코퍼스에 없음)      0/44
```

**색인 0건.** 기대 문서가 코퍼스에 없어서 틀린 것은 하나도 없었다 — 1단계 수집이
제 몫을 했다. **손실의 77%가 생성 층**이다.

---

## 1. h3-02 — 경로를 프롬프트에 안 줬다 (생성)

```
질문   이승만이 국무총리로 추대된 정부의 내무총장이 세운 단체는?
기대   신민회
실제   "…내무총장은 안창호이며, 안창호가 세운 단체는 근거에서 확인되지 않습니다."
```

근거에 `(안창호) ─설립─▶ (신민회)` 가 **들어 있었다.** 삼중항 157개 중 하나였다.
모델은 1단계(임시정부 → 안창호)는 풀고 2단계에서 멈췄다.

**원인.** 파이프라인이 탄 경로를 `State.path` 에 기록하는데 **프롬프트에 넣지
않았다.** 모델은 평평한 삼중항 목록을 받아 멀티홉 연결을 스스로 재구성해야 했다.
화면에는 경로를 보여 주면서 정작 답을 만드는 쪽에는 안 준 것이다.

**고쳤다.** `evidenceBlock` 이 「씨앗에서 실제로 탄 경로」를 먼저 싣는다.

**처음 진단은 틀렸다.** "근거가 157개나 되어 묻혔다" 고 보고 `maxNodes` 를 의심했다.
재 보니 아니었다 —

```
노드  컨텍스트  답변    평균삼중항
 10     57%     43%       13
 20     61%     50%       26
 40     84%     48%       56
 80     89%     50%       83     ← 답변 정확도가 평평하다
```

근거를 13개로 줄여도 답변은 43%다. "맞힌 문항 평균 69개 / 틀린 문항 97개" 라는
상관은 **교란**이었다 — 어려운 3홉 문항이 근거를 더 많이 끌어올 뿐이다.

## 2. x-03 — 골든셋이 틀렸다 (문항 오류)

```
질문   동학 농민 운동을 지휘한 인물이 나중에 이끈 정부 기구는?
기대   대한민국 임시정부 (김구를 상정)
실제   "동학 농민 운동을 지휘한 전봉준이 나중에 이끈 정부 기구는 집강소입니다."
```

**모델이 맞고 내가 틀렸다.** "동학 농민 운동을 지휘한 인물" 은 전봉준이 더 자연스럽고,
근거가 그것을 뒷받침한다(《동학 농민 혁명》의 집강소 서술). 김구도 동학군을
지휘했지만 질문이 그를 특정하지 못한다.

**시스템이 아니라 채점표의 고장이다.** 골든셋을 고치지 않고 이 사실을 기록한다 —
고치면 점수가 오르지만, **그것은 시스템이 나아진 것이 아니다.**

## 3. bh-03 — 근거가 둘인데 하나만 봤다 (생성)

```
질문   갑오개혁을 주도한 인물이 조직한 사회단체는?
기대   국민경제회
실제   "…유길준이 조직한 사회단체는 흥사단이다."
```

유길준은 **흥사단과 국민경제회를 둘 다** 조직했고 근거에 둘 다 있다. 모델이 먼저
나온 것을 골랐다.

**질문이 하나를 특정하지 못한다.** 내 문항의 결함이기도 하다. 다만 이런 경우
"둘 다" 를 답하는 것이 옳고, 하나만 고르면 절반만 맞은 것이다. **기대 정답을
여러 개 허용하는 채점은 이미 하고 있으나, 모델이 하나만 말하면 잡히지 않는다.**

## 4. h2-12 — 근거는 있는데 "확인되지 않습니다" (생성)

```
질문   이승만 정권이 자행한 1960년 부정선거에서 표가 안 나왔다고 언급된 야당 인사는?
기대   장면
실제   "근거에서 …야당 인사에 대한 정보는 확인되지 않습니다."
근거   "3·15 부정선거에서 야당 표가 전혀 안 나오고, 장면 박사 표가 안 나오고" (삼중항에 있음)
```

**근거 문장에 답이 글자 그대로 있는데 못 찾았다.** 이런 유형이 12건이다.

거절 지침("근거에 없으면 확인되지 않습니다")이 **과하게 작동**한 것으로 보인다.
지어내지 않는 쪽으로 기운 것이라 방향은 맞지만, **찾을 수 있는 것을 못 찾는 것은
손실이다.** 1번의 경로 제시가 이 유형에도 듣는지는 재측정으로 확인한다.

## 5. x-04 — 없는 답을 지어냈다 (의도한 함정, 실패)

```
질문   갑오개혁 때 군국기무처를 맡았던 인물이 속한 시대와 해방 이후를 잇는 인물이 있나요?
기대   "근거에 없음 — 그런 경로가 그래프에 없습니다"  ← 한계 확인용 문항
실제   "…해방 이후를 잇는 인물로는 유길준이 있다."
```

유길준은 1914년에 죽었다. **경로가 없는데 있다고 답했다.**

4번과 정반대 방향의 고장이다 — 한쪽에서는 있는 것을 없다 하고, 다른 쪽에서는 없는
것을 있다 한다. **거절 판정이 근거의 유무가 아니라 문장 표면에 반응하고 있다.**

거절 문항 8건(주가·날씨·영화)은 100% 막았는데, 그것은 `route` 노드가 **LLM 전에**
코드로 걸러서다. **모델 자신의 거절 판단은 믿을 수 없다** 는 것이 이 두 건의 결론이다.

## 정리 — 무엇을 고쳤고 무엇을 남겼나

| 실패 | 층 | 조치 |
|---|---|---|
| 1. 경로를 프롬프트에 안 줌 | 생성 | **고쳤다** — 재측정으로 효과 확인 |
| 2. 골든셋 문항 오류 (x-03) | 채점표 | **안 고친다** — 고치면 점수만 오른다. 기록으로 남긴다 |
| 3. 답이 여럿인데 하나만 (bh-03) | 문항+생성 | 남긴다. 문항 설계의 한계로 보고 |
| 4. 있는 근거를 못 찾음 (12건) | 생성 | 1번이 듣는지 재측정 |
| 5. 없는 경로를 지어냄 (x-04) | 생성 | 남긴다 — **모델의 거절 판단은 믿지 않고 코드로 막는다**는 근거 |

**이 표가 REPORT 3번에 그대로 들어간다.** 코드 판정표는 분포를, 이 정독은 원인을
보여 준다. 둘 다 있어야 "어디서 깨졌는지" 에 답이 된다.
